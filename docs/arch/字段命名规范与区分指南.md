# 字段命名规范与区分指南

## 概述

本文档旨在明确区分系统中三个不同层次的字段命名，避免混淆：
- **MongoDB 数据库字段**：存储在 MongoDB 中的文档字段
- **TDLib API 字段**：Telegram TDLib 库返回的对象字段
- **RESTful API 字段**：系统对外提供的 REST API 接口字段

## 1. 核心概念

### 1.1 三层架构

```
┌─────────────────────────────────────────────────────────────┐
│                      RESTful API 层                          │
│  - 对外接口                                                   │
│  - DTO/VO 对象                                               │
│  - 字段：id (MongoDB ID), channelId (TG ID)                 │
└─────────────────────────────────────────────────────────────┘
                            ↕
┌─────────────────────────────────────────────────────────────┐
│                      业务逻辑层                               │
│  - Service 层                                                │
│  - 数据转换                                                   │
│  - 业务规则                                                   │
└─────────────────────────────────────────────────────────────┘
                            ↕
┌─────────────────────────────────────────────────────────────┐
│                      数据持久层                               │
│  - MongoDB Entity                                            │
│  - 字段：_id (MongoDB ID), channelId (TG ID)                │
└─────────────────────────────────────────────────────────────┘
                            ↕
┌─────────────────────────────────────────────────────────────┐
│                      TDLib 层                                │
│  - Telegram API                                              │
│  - TdApi 对象                                                │
│  - 字段：id (TG User ID), chatId (TG Chat ID)               │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 ID 类型说明

| ID 类型 | 数据类型 | 格式 | 示例 | 用途 |
|---------|---------|------|------|------|
| MongoDB 文档 ID | String | 24位十六进制 | `"65f8a1b2c3d4e5f6a7b8c9d0"` | 数据库主键 |
| Telegram Chat ID | Long | 负数（频道）或正数（用户） | `-1001234567890` | TG 聊天标识 |
| Telegram Message ID | Long | 正整数 | `123456` | TG 消息标识 |
| Telegram User ID | Long | 正整数 | `987654321` | TG 用户标识 |

## 2. 频道相关字段

### 2.1 字段对照表

| 概念 | MongoDB | TDLib | RESTful API | 说明 |
|------|---------|-------|-------------|------|
| 文档主键 | `_id` | - | `id` | MongoDB 自动生成的文档 ID |
| 频道 ID | `channelId` | `chatId` | `channelId` | Telegram 频道的唯一标识 |
| 频道用户名 | `channelUsername` | `username` | `channelUsername` | 频道的 @ 用户名（不含@） |
| 频道标题 | `channelTitle` | `title` | `channelTitle` | 频道显示名称 |
| 监控状态 | `monitoringStatus` | - | `monitoringStatus` | 系统特有字段 |
| 创建时间 | `createTime` | - | `createTime` | 系统特有字段 |
| 更新时间 | `updateTime` | - | `updateTime` | 系统特有字段 |

### 2.2 MongoDB Entity (Channel)

```java
@Document(collection = "telegram_channels")
public class Channel {
    @Id
    private String id;                    // MongoDB 文档 ID
    
    @Indexed(unique = true)
    private Long channelId;               // Telegram 频道 ID
    
    private String channelUsername;       // 频道用户名
    private String channelTitle;          // 频道标题
    private Boolean monitoringStatus;     // 监控状态
    private LocalDateTime createTime;     // 创建时间
    private LocalDateTime updateTime;     // 更新时间
}
```

### 2.3 TDLib API (Chat)

```java
// TdApi.Chat 对象
public class Chat {
    public long id;                       // 聊天 ID（即频道 ID）
    public ChatType type;                 // 聊天类型
    public String title;                  // 标题
    // ... 其他字段
}

// TdApi.Supergroup 对象
public class Supergroup {
    public long id;                       // 超级群组 ID
    public String username;               // 用户名
    public int memberCount;               // 成员数
    public boolean isChannel;             // 是否为频道
    // ... 其他字段
}
```

### 2.4 RESTful API (ChannelVO)

```java
public class ChannelVO {
    private String id;                    // MongoDB 文档 ID
    private Long channelId;               // Telegram 频道 ID
    private String channelUsername;       // 频道用户名
    private String channelTitle;          // 频道标题
    private Boolean monitoringStatus;     // 监控状态
    private LocalDateTime createTime;     // 创建时间
    private LocalDateTime updateTime;     // 更新时间
}
```

### 2.5 关键区别

**⚠️ 重要：`id` 字段的含义**

- **RESTful API 中的 `id`**：指 MongoDB 文档 ID（String 类型）
  ```json
  {
    "id": "65f8a1b2c3d4e5f6a7b8c9d0",  // MongoDB ID
    "channelId": -1001234567890         // Telegram ID
  }
  ```

- **TDLib API 中的 `id`**：指 Telegram 对象 ID（Long 类型）
  ```java
  TdApi.Chat chat = ...;
  long chatId = chat.id;  // Telegram Chat ID
  ```

**示例：删除频道 API**

```java
// ❌ 错误理解
@DeleteMapping("/{id}")
public ApiResponse<Void> deleteChannel(@PathVariable String id) {
    // id 是 MongoDB 文档 ID，不是 Telegram 频道 ID！
}

// ✅ 正确使用
// 传入 MongoDB ID: "65f8a1b2c3d4e5f6a7b8c9d0"
DELETE /api/channel/65f8a1b2c3d4e5f6a7b8c9d0

// 如果要通过 Telegram ID 删除，需要另外的接口
@DeleteMapping("/by-tg-id/{channelId}")
public ApiResponse<Void> deleteByTgId(@PathVariable Long channelId) {
    // channelId 是 Telegram 频道 ID
}
```

## 3. 消息相关字段

### 3.1 字段对照表

| 概念 | MongoDB | TDLib | RESTful API | 说明 |
|------|---------|-------|-------------|------|
| 文档主键 | `_id` | - | `id` | MongoDB 文档 ID |
| 频道 ID | `chatId` | `chatId` | `chatId` | 消息所属频道 |
| 消息 ID | `messageId` | `id` | `messageId` | 单条消息标识 |
| 媒体组 ID | `mediaAlbumId` | `mediaAlbumId` | `mediaAlbumId` | 媒体组标识 |
| 消息日期 | `date` | `date` | `date` | Unix 时间戳 |
| 原始 JSON | `rawJson` | - | - | TDLib 对象序列化 |

### 3.2 MongoDB Entity (RawMessage)

```java
@Document(collection = "raw_messages")
public class RawMessage {
    @Id
    private String id;                    // MongoDB 文档 ID
    
    @Indexed
    private Long chatId;                  // 频道 ID（来自 TDLib）
    
    @Indexed
    private Long messageId;               // 消息 ID（来自 TDLib）
    
    @Indexed
    private Long mediaAlbumId;            // 媒体组 ID（来自 TDLib）
    
    private Integer date;                 // 消息日期（Unix 时间戳）
    private String rawJson;               // TDLib 原始 JSON
    private LocalDateTime createTime;     // 系统创建时间
    private LocalDateTime updateTime;     // 系统更新时间
}
```

### 3.3 TDLib API (Message)

```java
// TdApi.Message 对象
public class Message {
    public long id;                       // 消息 ID
    public long chatId;                   // 聊天 ID
    public long mediaAlbumId;             // 媒体组 ID（0 表示非媒体组）
    public int date;                      // 消息日期（Unix 时间戳）
    public MessageContent content;        // 消息内容
    // ... 其他字段
}
```

### 3.4 关键区别

**⚠️ 重要：消息 ID 的含义**

- **MongoDB 中的 `id`**：文档主键（String）
- **MongoDB 中的 `messageId`**：Telegram 消息 ID（Long）
- **TDLib 中的 `id`**：Telegram 消息 ID（Long）

```java
// TDLib 消息对象
TdApi.Message message = ...;
long tgMessageId = message.id;        // Telegram 消息 ID
long tgChatId = message.chatId;       // Telegram 频道 ID

// 保存到 MongoDB
RawMessage rawMessage = new RawMessage();
rawMessage.setMessageId(tgMessageId); // 存储 TG 消息 ID
rawMessage.setChatId(tgChatId);       // 存储 TG 频道 ID
// rawMessage.id 由 MongoDB 自动生成
```

## 5. 常见混淆场景

### 5.1 场景 1：删除频道接口

**问题**：`DELETE /api/channel/{id}` 中的 `id` 是什么？

**答案**：MongoDB 文档 ID（String 类型）

```java
// 控制器方法
@DeleteMapping("/{id}")
public ApiResponse<Void> deleteChannel(@PathVariable String id) {
    // id = "65f8a1b2c3d4e5f6a7b8c9d0" (MongoDB ID)
    channelService.deleteById(id);
    return ApiResponse.success();
}

// Service 层
public void deleteById(String id) {
    // 1. 通过 MongoDB ID 查询
    Channel channel = channelRepository.findById(id)
        .orElseThrow(() -> new BusinessException(
            ResponseCode.DATA_NOT_FOUND, 
            "频道不存在: " + id
        ));
    
    // 2. 获取 Telegram 频道 ID
    Long channelId = channel.getChannelId();
    
    // 3. 删除数据库记录
    channelRepository.deleteById(id);
    
    // 4. 发布事件（使用 Telegram ID）
    eventPublisher.publishEvent(
        ChannelMonitoringEvent.channelRemoved(this, channelId)
    );
}
```

**正确调用**：
```bash
# 使用 MongoDB ID
DELETE /api/channel/65f8a1b2c3d4e5f6a7b8c9d0
```

**错误调用**：
```bash
# ❌ 错误：使用 Telegram ID
DELETE /api/channel/-1001234567890
# 结果：404 Not Found（MongoDB 中不存在这个 ID）
```

### 5.2 场景 2：查询消息

**问题**：如何通过 Telegram 消息 ID 查询消息？

**答案**：需要同时提供 `chatId` 和 `messageId`

```java
// Repository 方法
Optional<RawMessage> findByChatIdAndMessageId(Long chatId, Long messageId);

// 使用示例
Optional<RawMessage> message = rawMessageRepository
    .findByChatIdAndMessageId(-1001234567890L, 123456L);
```

**为什么需要两个参数？**
- `messageId` 在单个频道内唯一
- 不同频道可能有相同的 `messageId`
- 因此需要 `chatId` + `messageId` 组合才能唯一确定一条消息

### 5.3 场景 3：创建频道

**问题**：创建频道时需要提供什么 ID？

**答案**：提供 Telegram 频道 ID（`channelId`），MongoDB ID 自动生成

```json
// 请求体
POST /api/channel
{
  "channelId": -1001234567890,    // Telegram 频道 ID（必填）
  "channelUsername": "tech_news",
  "channelTitle": "科技新闻"
}

// 响应体
{
  "code": 200,
  "data": {
    "id": "65f8a1b2c3d4e5f6a7b8c9d0",  // MongoDB ID（自动生成）
    "channelId": -1001234567890,        // Telegram ID（用户提供）
    "channelUsername": "tech_news",
    "channelTitle": "科技新闻"
  }
}
```

### 5.4 场景 4：TDLib 消息处理

**问题**：从 TDLib 接收消息后如何保存？

**答案**：提取 TDLib 字段映射到 MongoDB 字段

```java
// TDLib 消息
TdApi.Message tdMessage = update.message;

// 创建 MongoDB 实体
RawMessage rawMessage = new RawMessage();
rawMessage.setChatId(tdMessage.chatId);           // TDLib chatId → MongoDB chatId
rawMessage.setMessageId(tdMessage.id);            // TDLib id → MongoDB messageId
rawMessage.setMediaAlbumId(tdMessage.mediaAlbumId); // TDLib mediaAlbumId → MongoDB mediaAlbumId
rawMessage.setDate(tdMessage.date);               // TDLib date → MongoDB date
rawMessage.setRawJson(serializeToJson(tdMessage)); // 序列化整个对象

// 保存（MongoDB 自动生成 _id）
rawMessageRepository.save(rawMessage);
```

## 6. 命名规范

### 6.1 MongoDB 字段命名

**规则**：
- 使用 camelCase
- 主键固定为 `_id`（Spring Data 映射为 `id`）
- Telegram 相关字段保持与 TDLib 一致的命名

**示例**：
```java
@Document
public class Channel {
    @Id
    private String id;              // MongoDB _id
    private Long channelId;         // Telegram 频道 ID
    private String channelUsername; // Telegram 用户名
    private String channelTitle;    // Telegram 标题
}
```

### 6.2 TDLib 字段命名

**规则**：
- 遵循 TDLib 官方命名
- 不要修改字段名
- 使用时注意类型转换

**示例**：
```java
TdApi.Chat chat = ...;
long id = chat.id;              // 聊天 ID
String title = chat.title;      // 标题
```

### 6.3 RESTful API 字段命名

**规则**：
- DTO/VO 使用 camelCase
- JSON 响应使用 camelCase
- 字段名应清晰表达含义

**示例**：
```json
{
  "id": "65f8a1b2c3d4e5f6a7b8c9d0",  // MongoDB ID
  "channelId": -1001234567890,        // Telegram ID
  "channelUsername": "tech_news",
  "channelTitle": "科技新闻"
}
```

### 6.4 命名对照表

| 层次 | 主键字段 | Telegram ID 字段 | 用户名字段 | 标题字段 |
|------|---------|-----------------|-----------|---------|
| MongoDB | `_id` (String) | `channelId` (Long) | `channelUsername` | `channelTitle` |
| TDLib | - | `id` (long) | `username` | `title` |
| RESTful API | `id` (String) | `channelId` (Long) | `channelUsername` | `channelTitle` |

## 7. 最佳实践

### 7.1 代码注释

**✅ 好的实践**：明确注释字段含义

```java
/**
 * 删除频道
 * 
 * @param id 频道的 MongoDB 文档 ID（不是 Telegram 频道 ID）
 * @return 成功响应
 */
@DeleteMapping("/{id}")
public ApiResponse<Void> deleteChannel(@PathVariable String id) {
    channelService.deleteById(id);
    return ApiResponse.success();
}
```

**❌ 坏的实践**：注释不清晰

```java
/**
 * 删除频道
 * 
 * @param id 频道 ID
 */
@DeleteMapping("/{id}")
public ApiResponse<Void> deleteChannel(@PathVariable String id) {
    // 哪个 ID？MongoDB 还是 Telegram？
}
```

### 7.2 变量命名

**✅ 好的实践**：使用明确的变量名

```java
// 明确区分两种 ID
String mongoId = "65f8a1b2c3d4e5f6a7b8c9d0";
Long telegramChannelId = -1001234567890L;

// 或使用前缀
String dbId = "65f8a1b2c3d4e5f6a7b8c9d0";
Long tgChannelId = -1001234567890L;
```

**❌ 坏的实践**：使用模糊的变量名

```java
String id = "65f8a1b2c3d4e5f6a7b8c9d0";  // 哪个 ID？
Long id2 = -1001234567890L;              // 更糟糕
```

### 7.3 API 文档

**✅ 好的实践**：在 API 文档中明确说明

```markdown
### 删除频道

**接口地址：** `DELETE /api/channel/{id}`

**路径参数：**
- `id`: 频道的 MongoDB 文档 ID（String 类型，24位十六进制）
  - 示例：`"65f8a1b2c3d4e5f6a7b8c9d0"`
  - 注意：不是 Telegram 频道 ID

**示例：**
```bash
DELETE /api/channel/65f8a1b2c3d4e5f6a7b8c9d0
```
```

### 7.4 错误消息

**✅ 好的实践**：错误消息中明确 ID 类型

```java
throw new BusinessException(
    ResponseCode.DATA_NOT_FOUND,
    "频道不存在（MongoDB ID）: " + id
);
```

**❌ 坏的实践**：错误消息模糊

```java
throw new BusinessException(
    ResponseCode.DATA_NOT_FOUND,
    "频道不存在: " + id  // 哪个 ID？
);
```

### 7.5 数据转换

**✅ 好的实践**：明确的转换方法

```java
public class ChannelConverter {
    
    /**
     * TDLib Chat 对象转换为 MongoDB Entity
     */
    public static Channel fromTdLibChat(TdApi.Chat chat, TdApi.Supergroup supergroup) {
        Channel channel = new Channel();
        channel.setChannelId(chat.id);              // TDLib id → MongoDB channelId
        channel.setChannelTitle(chat.title);        // TDLib title → MongoDB channelTitle
        channel.setChannelUsername(supergroup.username); // TDLib username → MongoDB channelUsername
        return channel;
    }
    
    /**
     * MongoDB Entity 转换为 API VO
     */
    public static ChannelVO toVO(Channel entity) {
        ChannelVO vo = new ChannelVO();
        vo.setId(entity.getId());                   // MongoDB _id → API id
        vo.setChannelId(entity.getChannelId());     // MongoDB channelId → API channelId
        vo.setChannelTitle(entity.getChannelTitle());
        vo.setChannelUsername(entity.getChannelUsername());
        return vo;
    }
}
```

### 7.6 查询方法命名

**✅ 好的实践**：方法名明确参数含义

```java
public interface ChannelRepository extends MongoRepository<Channel, String> {
    
    // 通过 MongoDB ID 查询（继承自 MongoRepository）
    Optional<Channel> findById(String id);
    
    // 通过 Telegram 频道 ID 查询
    Optional<Channel> findByChannelId(Long channelId);
    
    // 通过 Telegram 用户名查询
    Optional<Channel> findByChannelUsername(String channelUsername);
}
```

**❌ 坏的实践**：方法名模糊

```java
// ❌ 不清楚是哪个 ID
Optional<Channel> findByTelegramId(Long id);
```

## 8. 快速参考

### 8.1 ID 类型速查表

| 场景 | 使用的 ID | 类型 | 示例 |
|------|----------|------|------|
| REST API 路径参数 | MongoDB ID | String | `/api/channel/65f8a1b2c3d4e5f6a7b8c9d0` |
| 创建频道请求 | Telegram ID | Long | `{"channelId": -1001234567890}` |
| TDLib 消息对象 | Telegram ID | long | `message.chatId = -1001234567890` |
| MongoDB 查询 | MongoDB ID | String | `findById("65f8a1b2c3d4e5f6a7b8c9d0")` |
| 频道监控事件 | Telegram ID | Long | `ChannelMonitoringEvent(channelId)` |

### 8.2 常用转换

```java
// TDLib → MongoDB
RawMessage rawMessage = new RawMessage();
rawMessage.setChatId(tdMessage.chatId);
rawMessage.setMessageId(tdMessage.id);

// MongoDB → API
ChannelVO vo = new ChannelVO();
vo.setId(entity.getId());
vo.setChannelId(entity.getChannelId());

// API → MongoDB 查询
String mongoId = request.getId();
Channel channel = repository.findById(mongoId).orElseThrow();
```
