## 1. 系统概述

### 1.1 什么是消息来源生成器？

消息来源生成器（Message Source Generator）是一个抽象层，用于将不同来源的消息统一转换为系统可处理的格式。
通过这个抽象，系统可以接收来自多种渠道的消息，而不仅限于 Telegram 官方 API。

### 1.2 为什么需要消息来源生成器？

- **解耦消息来源和处理逻辑**：消息处理系统不需要关心消息从哪里来
- **支持多种消息来源**：可以同时接收来自 Telegram、Webhook、文件导入等多种来源的消息
- **易于扩展**：添加新的消息来源只需实现接口，无需修改现有代码
- **统一管理**：通过注册表统一管理所有消息来源的生命周期和健康状态

### 1.3 核心特性

- **插件化架构**：消息来源作为独立组件，可动态注册和注销
- **统一接口**：所有消息来源实现相同的接口，保证一致性
- **生命周期管理**：支持启动、停止、健康检查等操作
- **监控和统计**：自动收集消息统计和健康指标
- **REST API 管理**：提供 HTTP 接口管理消息来源

## 2. 核心概念

### 2.1 消息来源（MessageSource）

消息来源是一个抽象接口，定义了消息来源的基本行为：

```java
public interface MessageSource {
    String getSourceId();           // 唯一标识符
    String getSourceName();         // 显示名称
    String getDescription();        // 描述信息
    void start();                   // 启动
    void stop();                    // 停止
    boolean isRunning();            // 运行状态
    MessageSourceHealth getHealth(); // 健康状态
}
```

### 2.2 消息来源注册表（MessageSourceRegistry）

注册表负责管理所有已注册的消息来源：

- 注册和注销消息来源
- 启动和停止消息来源
- 查询消息来源状态
- 获取健康状态

### 2.3 健康状态（MessageSourceHealth）

健康状态包含消息来源的运行指标：


- **状态**：HEALTHY（健康）、DEGRADED（降级）、UNHEALTHY（不健康）、UNKNOWN（未知）
- **统计指标**：接收消息数、处理消息数、失败消息数
- **时间信息**：启动时间、最后消息时间、最后检查时间
- **自定义指标**：特定于消息来源的额外指标

## 4. 快速开始

### 4.1 官方 Telegram 消息来源

系统默认包含官方 Telegram 消息来源，它通过 TDLight 库监听 Telegram API：

**特点**：
- 自动在应用启动时注册和启动
- 监听 `UpdateNewMessage` 事件
- 只处理频道消息（`isChannelPost = true`）
- 自动记录统计指标

**配置**：
无需额外配置，Telegram 客户端由 `TelegramClientManager` 管理。


**工作流程**：

```java
TDLight UpdateNewMessage 事件
    ↓
TgUpdateNewMessageHandler.onNewMessageUpdate()
    ↓
TelegramMessageSource.handleNewMessage()
    ↓
ChannelMonitorService.handleNewMessage()

```

### 5.1 实现步骤

#### 步骤 1：创建消息来源类

继承 `AbstractMessageSource` 并实现必要的方法：

```java

@RequiredArgsConstructor
public class WebhookMessageSource extends AbstractMessageSource {
    
    @Override

    }
    
    @Override
    public String getSourceName() {

    }
    
    @Override
    public String getDescription() {
        return "通过 HTTP Webhook 接收外部消息";
    }
    
    @Override
    protected void doStart() throws Exception {
        // 启动 Webhook 服务器或注册监听器
        log.info("Webhook 消息来源已启动");
    }
    
    @Override
    protected void doStop() throws Exception {
        // 停止 Webhook 服务器或注销监听器
        log.info("Webhook 消息来源已停止");
    }
}
```

#### 步骤 2：处理接收到的消息

```java
@Component
@RequiredArgsConstructor
public class WebhookMessageSource extends AbstractMessageSource {
    
    private final ChannelMonitorService channelMonitorService;
    
    /**
     * 接收 Webhook 消息
     */
    public void handleWebhookMessage(WebhookPayload payload) {
        try {
            // 记录接收到消息
            recordMessageReceived();
            
            // 转换为 TdApi.Message 格式
            TdApi.Message message = convertToTdMessage(payload);
            
            // 转发给消息处理系统
            channelMonitorService.handleNewMessage(message);
            
            // 记录处理成功
            recordMessageProcessed();
            
        } catch (Exception e) {
            log.error("处理 Webhook 消息失败", e);
            recordMessageFailed("处理失败: " + e.getMessage());
        }
    }
    
    /**
     * 转换为 TdApi.Message 格式
     */
    private TdApi.Message convertToTdMessage(WebhookPayload payload) {
        TdApi.Message message = new TdApi.Message();
        message.id = payload.getMessageId();
        message.chatId = payload.getChatId();
        message.date = (int) (payload.getTimestamp() / 1000);
        message.isChannelPost = true;
        
        // 设置消息内容
        TdApi.MessageText content = new TdApi.MessageText();
        content.text = new TdApi.FormattedText();
        content.text.text = payload.getText();
        message.content = content;
        
        return message;
    }
}
```


#### 步骤 3：注册消息来源

在配置类中注册自定义消息来源：

```java
@Configuration
@RequiredArgsConstructor
public class MessageSourceConfiguration {
    
    private final MessageSourceRegistry registry;
    private final TelegramMessageSource telegramMessageSource;
    private final WebhookMessageSource webhookMessageSource;
    
    @PostConstruct
    public void initMessageSources() {
        // 注册 Telegram 官方来源
        registry.register(telegramMessageSource);
        registry.startSource(telegramMessageSource.getSourceId());
        
        // 注册 Webhook 自定义来源
        registry.register(webhookMessageSource);
        registry.startSource(webhookMessageSource.getSourceId());
    }
}
```

### 5.2 完整示例：文件导入消息来源

```java
@Component
@RequiredArgsConstructor
@Slf4j
public class FileImportMessageSource extends AbstractMessageSource {
    
    private final ChannelMonitorService channelMonitorService;
    private final ObjectMapper objectMapper;
    
    private ScheduledExecutorService scheduler;
    
    @Value("${message-source.file-import.directory:./import}")
    private String importDirectory;
    
    @Value("${message-source.file-import.interval:60}")
    private int scanIntervalSeconds;
    
    @Override
    public String getSourceId() {
        return "file-import";
    }
    
    @Override
    public String getSourceName() {
        return "文件导入来源";
    }
    
    @Override
    public String getDescription() {
        return "从指定目录扫描并导入 JSON 格式的消息文件";
    }
    
    @Override
    protected void doStart() throws Exception {
        // 创建导入目录
        Path importPath = Paths.get(importDirectory);
        if (!Files.exists(importPath)) {
            Files.createDirectories(importPath);
        }
        
        // 启动定时扫描任务
        scheduler = Executors.newSingleThreadScheduledExecutor();
        scheduler.scheduleWithFixedDelay(
            this::scanAndImport,
            0,
            scanIntervalSeconds,
            TimeUnit.SECONDS
        );
        
        log.info("文件导入消息来源已启动，扫描目录: {}, 间隔: {}秒", 
            importDirectory, scanIntervalSeconds);
    }
    
    @Override
    protected void doStop() throws Exception {
        if (scheduler != null) {
            scheduler.shutdown();
            scheduler.awaitTermination(10, TimeUnit.SECONDS);
        }
        
        log.info("文件导入消息来源已停止");
    }
    
    @Override
    protected void addCustomHealthMetrics(MessageSourceHealth health) {
        health.addMetric("import_directory", importDirectory);
        health.addMetric("scan_interval_seconds", scanIntervalSeconds);
    }
    
    /**
     * 扫描并导入消息文件
     */
    private void scanAndImport() {
        try {
            Path importPath = Paths.get(importDirectory);
            
            try (Stream<Path> files = Files.list(importPath)) {
                files.filter(path -> path.toString().endsWith(".json"))
                    .forEach(this::importFile);
            }
            
        } catch (Exception e) {
            log.error("扫描导入目录失败", e);
            recordError("扫描失败: " + e.getMessage());
        }
    }
    
    /**
     * 导入单个文件
     */
    private void importFile(Path filePath) {
        try {
            log.info("导入消息文件: {}", filePath.getFileName());
            
            // 读取 JSON 文件
            String json = Files.readString(filePath);
            MessageImportDTO dto = objectMapper.readValue(json, MessageImportDTO.class);
            
            // 转换为 TdApi.Message
            TdApi.Message message = convertToTdMessage(dto);
            
            // 记录接收
            recordMessageReceived();
            
            // 处理消息
            channelMonitorService.handleNewMessage(message);
            
            // 记录成功
            recordMessageProcessed();
            
            // 移动到已处理目录
            Path processedDir = Paths.get(importDirectory, "processed");
            Files.createDirectories(processedDir);
            Files.move(filePath, processedDir.resolve(filePath.getFileName()));
            
            log.info("消息文件导入成功: {}", filePath.getFileName());
            
        } catch (Exception e) {
            log.error("导入消息文件失败: {}", filePath.getFileName(), e);
            recordMessageFailed("导入失败: " + e.getMessage());
            
            // 移动到失败目录
            try {
                Path failedDir = Paths.get(importDirectory, "failed");
                Files.createDirectories(failedDir);
                Files.move(filePath, failedDir.resolve(filePath.getFileName()));
            } catch (IOException ex) {
                log.error("移动失败文件失败", ex);
            }
        }
    }
    
    private TdApi.Message convertToTdMessage(MessageImportDTO dto) {
        // 转换逻辑（省略）
        return new TdApi.Message();
    }
}
```

### 6.1 MessageSource 接口

```java
public interface MessageSource {
    /**
     * 获取消息来源的唯一标识符
     * 建议格式：小写字母-连字符，如 "telegram-official"

     * 检查消息来源是否正在运行
     */
    boolean isRunning();
    
    /**
     * 获取消息来源的健康状态
     */
    MessageSourceHealth getHealth();
}
```

## 7. 最佳实践

### 7.1 消息来源设计原则

#### ✅ 好的实践

1. **单一职责**
   ```java
   // ✅ 好：只负责接收和转换消息
   public class WebhookMessageSource extends AbstractMessageSource {
       public void handleWebhook(Payload payload) {
           TdApi.Message message = convert(payload);
           channelMonitorService.handleNewMessage(message);
       }
   }
   ```

2. **非阻塞启动**
   ```java
   // ✅ 好：在后台线程中执行长时间任务
   @Override
   protected void doStart() throws Exception {
       scheduler = Executors.newScheduledThreadPool(1);
       scheduler.scheduleAtFixedRate(this::poll, 0, 10, TimeUnit.SECONDS);
   }
   ```

3. **优雅关闭**
   ```java
   // ✅ 好：等待任务完成后再关闭
   @Override
   protected void doStop() throws Exception {
       scheduler.shutdown();
       scheduler.awaitTermination(10, TimeUnit.SECONDS);
   }
   ```


4. **完善的错误处理**
   ```java
   // ✅ 好：捕获异常并记录
   public void handleMessage(Payload payload) {
       try {
           recordMessageReceived();
           processMessage(payload);
           recordMessageProcessed();
       } catch (Exception e) {
           log.error("处理消息失败", e);
           recordMessageFailed(e.getMessage());
       }
   }
   ```

5. **详细的健康指标**
   ```java
   // ✅ 好：提供丰富的监控信息
   @Override
   protected void addCustomHealthMetrics(MessageSourceHealth health) {
       health.addMetric("connection_status", isConnected());
       health.addMetric("queue_size", getQueueSize());
       health.addMetric("latency_ms", getLatency());
   }
   ```

#### ❌ 避免的做法

1. **阻塞启动**
   ```java
   // ❌ 坏：阻塞主线程
   @Override
   protected void doStart() throws Exception {
       while (true) {
           pollMessages(); // 永久阻塞
       }
   }
   ```

2. **忽略异常**
   ```java
   // ❌ 坏：吞掉异常
   public void handleMessage(Payload payload) {
       try {
           processMessage(payload);
       } catch (Exception e) {
           // 什么都不做
       }
   }
   ```

3. **不清理资源**
   ```java
   // ❌ 坏：不关闭连接
   @Override
   protected void doStop() throws Exception {
       // 没有关闭 HTTP 客户端、线程池等
   }
   ```

## 8. 故障排查

### 8.1 常见问题

#### 问题 1：消息来源无法启动

**症状**：调用 `start()` 方法抛出异常

**可能原因**：
- 依赖的服务未就绪（如数据库、外部 API）
- 配置错误（如端口被占用、文件路径不存在）
- 权限不足

**解决方法**：
1. 检查日志中的详细错误信息
2. 验证依赖服务是否正常
3. 检查配置文件
4. 确保有足够的权限


#### 问题 2：消息未被处理

**症状**：消息来源接收到消息，但未进入处理流程

**可能原因**：
- 消息被过滤器拒绝（如频道未监控、消息重复）
- 消息格式不正确（缺少必需字段）
- `isChannelPost` 未设置为 `true`

**解决方法**：
1. 检查过滤器日志，查看拒绝原因
2. 验证消息格式是否正确
3. 确保 `message.isChannelPost = true`
4. 检查频道是否在监控列表中

#### 问题 3：健康状态显示 UNHEALTHY

**症状**：`getHealth()` 返回 UNHEALTHY 状态

**可能原因**：
- 消息来源未运行
- 最近发生错误
- 长时间未接收到消息

**解决方法**：
1. 检查 `isRunning()` 状态
2. 查看 `lastError` 字段
3. 检查 `lastMessageTime`，确认是否有消息流入
4. 重启消息来源

#### 问题 4：内存泄漏

**症状**：长时间运行后内存持续增长

**可能原因**：
- 缓存未清理
- 线程未关闭
- 资源未释放

**解决方法**：
1. 检查是否有未清理的缓存
2. 确保 `doStop()` 中关闭了所有线程和连接
3. 使用 try-with-resources 管理资源
4. 定期清理过期数据

```java
@Component
public class PollingMessageSource extends AbstractMessageSource {
    
    @Override
    protected void doStart() throws Exception {
        scheduler = Executors.newScheduledThreadPool(1);
        scheduler.scheduleAtFixedRate(
            this::pollMessages,
            0,
            30,
            TimeUnit.SECONDS
        );
    }
    
    private void pollMessages() {
        try {
            List<ExternalMessage> messages = externalApi.fetchMessages();
            
            for (ExternalMessage msg : messages) {
                recordMessageReceived();
                TdApi.Message tdMessage = convert(msg);
                channelMonitorService.handleNewMessage(tdMessage);
                recordMessageProcessed();
            }
            
        } catch (Exception e) {
            log.error("拉取消息失败", e);
            recordError(e.getMessage());
        }
    }
}
```

## 11. 未读消息来源生成器

### 11.1 概述

未读消息来源生成器（UnreadMessageSource）是一个专门用于获取监控频道未读消息的消息来源实现。它在程序启动时或按需检测未读消息，确保程序未运行期间产生的消息不会被遗漏。

### 11.2 核心特性

- **启动时自动检测**：可配置在程序启动时自动检测未读消息
- **手动触发检测**：支持通过 API 手动触发未读消息检测
- **消息缓冲机制**：使用 MongoDB 缓冲区避免程序重启时重复获取
- **并发安全**：防止多个检测任务同时运行
- **错误隔离**：单个频道的错误不影响其他频道
- **速率限制**：使用 Resilience4j RateLimiter 避免触发 Telegram API 限制
- **批量处理**：支持批量获取和处理消息
- **统计监控**：提供详细的统计信息和健康指标

### 11.3 架构设计

```
UnreadMessageSource (主组件)
├── UnreadMessageSourceService (核心服务)
│   ├── 初始化服务并处理待处理的缓冲消息
│   ├── 检测未读消息（启动时自动或手动触发）
│   ├── 并发控制，防止多个检测任务同时运行
│   └── 统计信息收集和报告
├── UnreadMessageFetchService (消息获取服务)
│   ├── 使用 TDLib getChatHistory API 获取消息历史
│   ├── 过滤已处理消息（查询 processed_messages 集合）
│   ├── 速率限制和重试机制
│   └── 错误处理（临时错误、速率限制、永久错误）
├── UnreadMessageBufferService (缓冲区服务)
│   ├── 保存消息到 unread_messages_buffer 集合
│   ├── 处理缓冲区中的待处理消息
│   ├── 更新消息处理状态
│   └── 错误处理和重试
├── ErrorHandler (错误处理器)
│   ├── 分类 API 错误（速率限制、临时错误、永久错误）
│   ├── 指数退避重试策略
│   └── 错误日志记录
└── UnreadMessageMetrics (监控指标)
    ├── 记录频道扫描次数
    ├── 记录检测到的消息数量
    ├── 记录处理成功/失败次数
    └── 记录检测耗时
```

### 11.4 工作流程

#### 11.4.1 启动时自动检测流程

```
1. 应用启动
   ↓
2. UnreadMessageSource.doStart()
   ↓
3. UnreadMessageSourceService.initialize()
   - 检查 unread_messages_buffer 中的待处理消息
   - 如果有待处理消息，调用 processPendingMessages()
   ↓
4. 如果配置了 autoDetectOnStartup = true
   ↓
5. UnreadMessageSourceService.detectUnreadMessages()
   - 获取所有启用监控的频道
   - 对每个频道调用 processChannel()
   ↓
6. UnreadMessageFetchService.fetchUnreadMessages()
   - 使用 TDLib getChatHistory API 获取消息
   - 过滤已处理消息（查询 processed_messages）
   - 按消息 ID 升序排序
   ↓
7. UnreadMessageBufferService.bufferAndProcessMessages()
   - 保存消息到 unread_messages_buffer
   - 调用 ChannelMonitorService.handleNewMessage()
   - 更新缓冲区状态为 PROCESSED
   ↓
8. 消息进入正常处理流程
   - 过滤器链
   - 消息解析
   - 插件处理
```

#### 11.4.2 手动触发检测流程

```
1. 调用 REST API 或直接调用 detectUnreadMessages()
   ↓
2. 检查并发标志（isDetecting）
   - 如果已有检测任务运行，抛出 IllegalStateException
   ↓
3. 执行检测流程（同启动时自动检测）
   ↓
4. 返回检测结果统计信息
   - 总频道数
   - 成功/失败频道数
   - 未读消息总数
   - 处理成功/失败消息数
   - 检测耗时
```

### 11.5 数据库集合

#### 11.5.1 unread_messages_buffer 集合

用于临时存储获取到的未读消息，支持程序重启后恢复处理。

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| _id | ObjectId | MongoDB 文档 ID |
| chatId | Long | 频道 ID（Telegram Chat ID） |
| messageId | Long | 消息 ID（Telegram Message ID） |
| fetchTime | DateTime | 获取时间 |
| status | String | 缓冲区状态（PENDING/PROCESSED/FAILED） |
| rawMessage | String | 序列化的 TdApi.Message 对象 |
| errorMessage | String | 错误信息（status=FAILED 时） |
| createTime | DateTime | 创建时间 |
| updateTime | DateTime | 更新时间 |

**索引**：

```javascript
// 复合唯一索引：确保每条消息只缓冲一次
db.unread_messages_buffer.createIndex(
  { "chatId": 1, "messageId": 1 },
  { unique: true, name: "idx_chat_message_unique" }
)

// 复合索引：用于查询待处理消息
db.unread_messages_buffer.createIndex(
  { "status": 1, "fetchTime": 1 },
  { name: "idx_status_fetchTime" }
)

// TTL 索引：自动清理已处理的消息（7天后）
db.unread_messages_buffer.createIndex(
  { "createTime": 1 },
  { expireAfterSeconds: 604800, name: "idx_ttl_createTime" }
)
```

**业务规则**：

- 每条消息只缓冲一次（通过 chatId + messageId 唯一索引保证）
- 消息处理成功后标记为 PROCESSED 状态
- 消息处理失败后标记为 FAILED 状态并记录错误信息
- PROCESSED 状态的消息会在 7 天后自动清理（TTL 索引）

### 11.7 速率限制

使用 Resilience4j RateLimiter 避免触发 Telegram API 限制：

```java
@Configuration
public class TelegramRateLimiterConfig {
    
    @Bean
    public RateLimiter telegramRateLimiter(UnreadMessageSourceConfig config) {
        RateLimiterConfig rateLimiterConfig = RateLimiterConfig.custom()
            .limitForPeriod(config.getRateLimitPerSecond())
            .limitRefreshPeriod(Duration.ofSeconds(1))
            .timeoutDuration(Duration.ofSeconds(10))
            .build();
        
        return RateLimiter.of("telegram-api", rateLimiterConfig);
    }
}
```

**使用方式**：

```java
// 在调用 TDLib API 前获取许可
RateLimiter.waitForPermission(rateLimiter);

// 调用 API
TdApi.Object result = client.send(request).get();
```

### 11.8 错误处理

#### 11.8.1 错误分类

系统将 Telegram API 错误分为三类：

1. **速率限制错误**（RateLimitException）
   - 错误码：429
   - 处理策略：等待指定时间后重试

2. **临时错误**（TemporaryErrorException）
   - 错误码：500, 502, 503, 504
   - 处理策略：使用指数退避重试

3. **永久错误**（PermanentErrorException）
   - 错误码：400, 401, 403, 404
   - 处理策略：记录错误，不重试

#### 11.8.2 重试策略

```java
// 指数退避重试
int attempt = 0;
while (attempt < maxRetryAttempts) {
    try {
        return fetchMessages(chatId);
    } catch (TemporaryErrorException e) {
        attempt++;
        long delay = retryDelayMs * (long) Math.pow(2, attempt - 1);
        Thread.sleep(delay);
    }
}
```

### 11.12 最佳实践

#### 11.12.1 配置建议

- **生产环境**：
  - `auto-detect-on-startup: true`（确保启动时检测未读消息）
  - `max-messages-per-fetch: 100`（避免单次获取过多消息）
  - `rate-limit-per-second: 1`（避免触发 API 限制）

- **开发环境**：
  - `auto-detect-on-startup: false`（避免频繁重启时重复检测）
  - `max-messages-per-fetch: 50`（减少测试数据量）

#### 11.12.2 监控建议

- 监控 `unread_message.messages.failed` 指标，及时发现处理失败的消息
- 监控 `unread_message.api.errors` 指标，及时发现 API 错误
- 定期检查 `unread_messages_buffer` 集合中 FAILED 状态的消息

#### 11.12.3 故障排查

**问题 1：未读消息未被检测到**

可能原因：
- 频道未启用监控（`monitoringStatus = false`）
- 消息已在 `processed_messages` 集合中
- API 调用失败

解决方法：
1. 检查频道监控状态
2. 查询 `processed_messages` 集合
3. 查看日志中的 API 错误

**问题 2：消息重复处理**

可能原因：
- `unread_messages_buffer` 缓冲区未正常工作
- `processed_messages` 集合未正常记录

解决方法：
1. 检查 `unread_messages_buffer` 索引
2. 检查 `processed_messages` 索引
3. 查看日志中的去重提示

**问题 3：检测任务无法启动**

可能原因：
- 已有检测任务正在运行
- 并发标志未正确重置

解决方法：
1. 等待当前检测任务完成
2. 重启应用（重置并发标志）
