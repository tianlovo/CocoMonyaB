## 1. 系统概述

### 1.1 什么是消息来源生成器？

消息来源生成器（Message Source Generator）是一个抽象层，用于将不同来源的消息统一转换为系统可处理的格式。
通过这个抽象，系统可以接收来自多种渠道的消息，而不仅限于 Telegram 官方 API。

### 1.2 为什么需要消息来源生成器？

- **解耦消息来源和处理逻辑**：消息处理系统不需要关心消息从哪里来
- **支持多种消息来源**：可以同时接收来自 Telegram、Webhook、文件导入等多种来源的消息
- **易于扩展**：添加新的消息来源只需实现接口，无需修改现有代码
- **统一管理**：通过注册表统一管理所有消息来源的生命周期和健康状态

### 1.3 核心特性

- **插件化架构**：消息来源作为独立组件，可动态注册和注销
- **统一接口**：所有消息来源实现相同的接口，保证一致性
- **生命周期管理**：支持启动、停止、健康检查等操作
- **监控和统计**：自动收集消息统计和健康指标
- **REST API 管理**：提供 HTTP 接口管理消息来源

## 2. 核心概念

### 2.1 消息来源（MessageSource）

消息来源是一个抽象接口，定义了消息来源的基本行为：

```java
public interface MessageSource {
    String getSourceId();           // 唯一标识符
    String getSourceName();         // 显示名称
    String getDescription();        // 描述信息
    void start();                   // 启动
    void stop();                    // 停止
    boolean isRunning();            // 运行状态
    MessageSourceHealth getHealth(); // 健康状态
}
```

### 2.2 消息来源注册表（MessageSourceRegistry）

注册表负责管理所有已注册的消息来源：

- 注册和注销消息来源
- 启动和停止消息来源
- 查询消息来源状态
- 获取健康状态

### 2.3 健康状态（MessageSourceHealth）

健康状态包含消息来源的运行指标：


- **状态**：HEALTHY（健康）、DEGRADED（降级）、UNHEALTHY（不健康）、UNKNOWN（未知）
- **统计指标**：接收消息数、处理消息数、失败消息数
- **时间信息**：启动时间、最后消息时间、最后检查时间
- **自定义指标**：特定于消息来源的额外指标

## 4. 快速开始

### 4.1 官方 Telegram 消息来源

系统默认包含官方 Telegram 消息来源，它通过 TDLight 库监听 Telegram API：

**特点**：
- 自动在应用启动时注册和启动
- 监听 `UpdateNewMessage` 事件
- 只处理频道消息（`isChannelPost = true`）
- 自动记录统计指标

**配置**：
无需额外配置，Telegram 客户端由 `TelegramClientManager` 管理。


**工作流程**：

```java
TDLight UpdateNewMessage 事件
    ↓
TgUpdateNewMessageHandler.onNewMessageUpdate()
    ↓
TelegramMessageSource.handleNewMessage()
    ↓
ChannelMonitorService.handleNewMessage()

```

### 5.1 实现步骤

#### 步骤 1：创建消息来源类

继承 `AbstractMessageSource` 并实现必要的方法：

```java

@RequiredArgsConstructor
public class WebhookMessageSource extends AbstractMessageSource {
    
    @Override

    }
    
    @Override
    public String getSourceName() {

    }
    
    @Override
    public String getDescription() {
        return "通过 HTTP Webhook 接收外部消息";
    }
    
    @Override
    protected void doStart() throws Exception {
        // 启动 Webhook 服务器或注册监听器
        log.info("Webhook 消息来源已启动");
    }
    
    @Override
    protected void doStop() throws Exception {
        // 停止 Webhook 服务器或注销监听器
        log.info("Webhook 消息来源已停止");
    }
}
```

#### 步骤 2：处理接收到的消息

```java
@Component
@RequiredArgsConstructor
public class WebhookMessageSource extends AbstractMessageSource {
    
    private final ChannelMonitorService channelMonitorService;
    
    /**
     * 接收 Webhook 消息
     */
    public void handleWebhookMessage(WebhookPayload payload) {
        try {
            // 记录接收到消息
            recordMessageReceived();
            
            // 转换为 TdApi.Message 格式
            TdApi.Message message = convertToTdMessage(payload);
            
            // 转发给消息处理系统
            channelMonitorService.handleNewMessage(message);
            
            // 记录处理成功
            recordMessageProcessed();
            
        } catch (Exception e) {
            log.error("处理 Webhook 消息失败", e);
            recordMessageFailed("处理失败: " + e.getMessage());
        }
    }
    
    /**
     * 转换为 TdApi.Message 格式
     */
    private TdApi.Message convertToTdMessage(WebhookPayload payload) {
        TdApi.Message message = new TdApi.Message();
        message.id = payload.getMessageId();
        message.chatId = payload.getChatId();
        message.date = (int) (payload.getTimestamp() / 1000);
        message.isChannelPost = true;
        
        // 设置消息内容
        TdApi.MessageText content = new TdApi.MessageText();
        content.text = new TdApi.FormattedText();
        content.text.text = payload.getText();
        message.content = content;
        
        return message;
    }
}
```


#### 步骤 3：注册消息来源

在配置类中注册自定义消息来源：

```java
@Configuration
@RequiredArgsConstructor
public class MessageSourceConfiguration {
    
    private final MessageSourceRegistry registry;
    private final TelegramMessageSource telegramMessageSource;
    private final WebhookMessageSource webhookMessageSource;
    
    @PostConstruct
    public void initMessageSources() {
        // 注册 Telegram 官方来源
        registry.register(telegramMessageSource);
        registry.startSource(telegramMessageSource.getSourceId());
        
        // 注册 Webhook 自定义来源
        registry.register(webhookMessageSource);
        registry.startSource(webhookMessageSource.getSourceId());
    }
}
```

### 5.2 完整示例：文件导入消息来源

```java
@Component
@RequiredArgsConstructor
@Slf4j
public class FileImportMessageSource extends AbstractMessageSource {
    
    private final ChannelMonitorService channelMonitorService;
    private final ObjectMapper objectMapper;
    
    private ScheduledExecutorService scheduler;
    
    @Value("${message-source.file-import.directory:./import}")
    private String importDirectory;
    
    @Value("${message-source.file-import.interval:60}")
    private int scanIntervalSeconds;
    
    @Override
    public String getSourceId() {
        return "file-import";
    }
    
    @Override
    public String getSourceName() {
        return "文件导入来源";
    }
    
    @Override
    public String getDescription() {
        return "从指定目录扫描并导入 JSON 格式的消息文件";
    }
    
    @Override
    protected void doStart() throws Exception {
        // 创建导入目录
        Path importPath = Paths.get(importDirectory);
        if (!Files.exists(importPath)) {
            Files.createDirectories(importPath);
        }
        
        // 启动定时扫描任务
        scheduler = Executors.newSingleThreadScheduledExecutor();
        scheduler.scheduleWithFixedDelay(
            this::scanAndImport,
            0,
            scanIntervalSeconds,
            TimeUnit.SECONDS
        );
        
        log.info("文件导入消息来源已启动，扫描目录: {}, 间隔: {}秒", 
            importDirectory, scanIntervalSeconds);
    }
    
    @Override
    protected void doStop() throws Exception {
        if (scheduler != null) {
            scheduler.shutdown();
            scheduler.awaitTermination(10, TimeUnit.SECONDS);
        }
        
        log.info("文件导入消息来源已停止");
    }
    
    @Override
    protected void addCustomHealthMetrics(MessageSourceHealth health) {
        health.addMetric("import_directory", importDirectory);
        health.addMetric("scan_interval_seconds", scanIntervalSeconds);
    }
    
    /**
     * 扫描并导入消息文件
     */
    private void scanAndImport() {
        try {
            Path importPath = Paths.get(importDirectory);
            
            try (Stream<Path> files = Files.list(importPath)) {
                files.filter(path -> path.toString().endsWith(".json"))
                    .forEach(this::importFile);
            }
            
        } catch (Exception e) {
            log.error("扫描导入目录失败", e);
            recordError("扫描失败: " + e.getMessage());
        }
    }
    
    /**
     * 导入单个文件
     */
    private void importFile(Path filePath) {
        try {
            log.info("导入消息文件: {}", filePath.getFileName());
            
            // 读取 JSON 文件
            String json = Files.readString(filePath);
            MessageImportDTO dto = objectMapper.readValue(json, MessageImportDTO.class);
            
            // 转换为 TdApi.Message
            TdApi.Message message = convertToTdMessage(dto);
            
            // 记录接收
            recordMessageReceived();
            
            // 处理消息
            channelMonitorService.handleNewMessage(message);
            
            // 记录成功
            recordMessageProcessed();
            
            // 移动到已处理目录
            Path processedDir = Paths.get(importDirectory, "processed");
            Files.createDirectories(processedDir);
            Files.move(filePath, processedDir.resolve(filePath.getFileName()));
            
            log.info("消息文件导入成功: {}", filePath.getFileName());
            
        } catch (Exception e) {
            log.error("导入消息文件失败: {}", filePath.getFileName(), e);
            recordMessageFailed("导入失败: " + e.getMessage());
            
            // 移动到失败目录
            try {
                Path failedDir = Paths.get(importDirectory, "failed");
                Files.createDirectories(failedDir);
                Files.move(filePath, failedDir.resolve(filePath.getFileName()));
            } catch (IOException ex) {
                log.error("移动失败文件失败", ex);
            }
        }
    }
    
    private TdApi.Message convertToTdMessage(MessageImportDTO dto) {
        // 转换逻辑（省略）
        return new TdApi.Message();
    }
}
```

### 6.1 MessageSource 接口

```java
public interface MessageSource {
    /**
     * 获取消息来源的唯一标识符
     * 建议格式：小写字母-连字符，如 "telegram-official"

     * 检查消息来源是否正在运行
     */
    boolean isRunning();
    
    /**
     * 获取消息来源的健康状态
     */
    MessageSourceHealth getHealth();
}
```

## 7. 最佳实践

### 7.1 消息来源设计原则

#### ✅ 好的实践

1. **单一职责**
   ```java
   // ✅ 好：只负责接收和转换消息
   public class WebhookMessageSource extends AbstractMessageSource {
       public void handleWebhook(Payload payload) {
           TdApi.Message message = convert(payload);
           channelMonitorService.handleNewMessage(message);
       }
   }
   ```

2. **非阻塞启动**
   ```java
   // ✅ 好：在后台线程中执行长时间任务
   @Override
   protected void doStart() throws Exception {
       scheduler = Executors.newScheduledThreadPool(1);
       scheduler.scheduleAtFixedRate(this::poll, 0, 10, TimeUnit.SECONDS);
   }
   ```

3. **优雅关闭**
   ```java
   // ✅ 好：等待任务完成后再关闭
   @Override
   protected void doStop() throws Exception {
       scheduler.shutdown();
       scheduler.awaitTermination(10, TimeUnit.SECONDS);
   }
   ```


4. **完善的错误处理**
   ```java
   // ✅ 好：捕获异常并记录
   public void handleMessage(Payload payload) {
       try {
           recordMessageReceived();
           processMessage(payload);
           recordMessageProcessed();
       } catch (Exception e) {
           log.error("处理消息失败", e);
           recordMessageFailed(e.getMessage());
       }
   }
   ```

5. **详细的健康指标**
   ```java
   // ✅ 好：提供丰富的监控信息
   @Override
   protected void addCustomHealthMetrics(MessageSourceHealth health) {
       health.addMetric("connection_status", isConnected());
       health.addMetric("queue_size", getQueueSize());
       health.addMetric("latency_ms", getLatency());
   }
   ```

#### ❌ 避免的做法

1. **阻塞启动**
   ```java
   // ❌ 坏：阻塞主线程
   @Override
   protected void doStart() throws Exception {
       while (true) {
           pollMessages(); // 永久阻塞
       }
   }
   ```

2. **忽略异常**
   ```java
   // ❌ 坏：吞掉异常
   public void handleMessage(Payload payload) {
       try {
           processMessage(payload);
       } catch (Exception e) {
           // 什么都不做
       }
   }
   ```

3. **不清理资源**
   ```java
   // ❌ 坏：不关闭连接
   @Override
   protected void doStop() throws Exception {
       // 没有关闭 HTTP 客户端、线程池等
   }
   ```

## 8. 故障排查

### 8.1 常见问题

#### 问题 1：消息来源无法启动

**症状**：调用 `start()` 方法抛出异常

**可能原因**：
- 依赖的服务未就绪（如数据库、外部 API）
- 配置错误（如端口被占用、文件路径不存在）
- 权限不足

**解决方法**：
1. 检查日志中的详细错误信息
2. 验证依赖服务是否正常
3. 检查配置文件
4. 确保有足够的权限


#### 问题 2：消息未被处理

**症状**：消息来源接收到消息，但未进入处理流程

**可能原因**：
- 消息被过滤器拒绝（如频道未监控、消息重复）
- 消息格式不正确（缺少必需字段）
- `isChannelPost` 未设置为 `true`

**解决方法**：
1. 检查过滤器日志，查看拒绝原因
2. 验证消息格式是否正确
3. 确保 `message.isChannelPost = true`
4. 检查频道是否在监控列表中

#### 问题 3：健康状态显示 UNHEALTHY

**症状**：`getHealth()` 返回 UNHEALTHY 状态

**可能原因**：
- 消息来源未运行
- 最近发生错误
- 长时间未接收到消息

**解决方法**：
1. 检查 `isRunning()` 状态
2. 查看 `lastError` 字段
3. 检查 `lastMessageTime`，确认是否有消息流入
4. 重启消息来源

#### 问题 4：内存泄漏

**症状**：长时间运行后内存持续增长

**可能原因**：
- 缓存未清理
- 线程未关闭
- 资源未释放

**解决方法**：
1. 检查是否有未清理的缓存
2. 确保 `doStop()` 中关闭了所有线程和连接
3. 使用 try-with-resources 管理资源
4. 定期清理过期数据

## 9. 示例场景

### 9.1 场景 1：Webhook 消息来源

接收来自外部系统的 HTTP Webhook 消息：

```java
@RestController
@RequestMapping("/webhook")
@RequiredArgsConstructor
public class WebhookController {
    
    private final WebhookMessageSource webhookMessageSource;
    
    @PostMapping("/message")
    public ResponseEntity<Void> receiveMessage(@RequestBody WebhookPayload payload) {
        webhookMessageSource.handleWebhookMessage(payload);
        return ResponseEntity.ok().build();
    }
}
```

### 9.2 场景 2：定时任务消息来源

定期从外部 API 拉取消息：

```java
@Component
public class PollingMessageSource extends AbstractMessageSource {
    
    @Override
    protected void doStart() throws Exception {
        scheduler = Executors.newScheduledThreadPool(1);
        scheduler.scheduleAtFixedRate(
            this::pollMessages,
            0,
            30,
            TimeUnit.SECONDS
        );
    }
    
    private void pollMessages() {
        try {
            List<ExternalMessage> messages = externalApi.fetchMessages();
            
            for (ExternalMessage msg : messages) {
                recordMessageReceived();
                TdApi.Message tdMessage = convert(msg);
                channelMonitorService.handleNewMessage(tdMessage);
                recordMessageProcessed();
            }
            
        } catch (Exception e) {
            log.error("拉取消息失败", e);
            recordError(e.getMessage());
        }
    }
}
```

### 9.3 场景 3：消息队列消息来源

从消息队列（如 RabbitMQ、Kafka）消费消息：

```java
@Component
public class QueueMessageSource extends AbstractMessageSource {
    
    @RabbitListener(queues = "telegram-messages")
    public void handleQueueMessage(String messageJson) {
        try {
            recordMessageReceived();
            
            QueueMessage queueMsg = objectMapper.readValue(messageJson, QueueMessage.class);
            TdApi.Message tdMessage = convert(queueMsg);
            
            channelMonitorService.handleNewMessage(tdMessage);
            recordMessageProcessed();
            
        } catch (Exception e) {
            log.error("处理队列消息失败", e);
            recordMessageFailed(e.getMessage());
        }
    }
}
```
