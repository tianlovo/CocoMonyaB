## 1. 快速开始

### 1.1 系统简介

本系统是一个基于 TDLight (Telegram) 的频道消息监控和处理框架，提供了灵活的过滤器链和插件机制，让开发者可以轻松实现自定义的消息处理逻辑。

### 1.2 核心特性

- **过滤器链**：在消息保存前进行多层过滤，支持自定义过滤规则
- **动态频道监控**：通过 REST API 动态增删改监控频道，实时生效无需重启
- **插件系统**：模块化的消息处理，支持多种消息类型
- **媒体组支持**：智能识别和批量处理媒体组消息
- **类型检测**：自动识别文本、图片、视频、Telegraph 等多种消息类型
- **并发安全**：线程安全的设计，支持高并发场景
- **易于扩展**：清晰的接口设计，方便添加新功能

### 1.3 5 分钟上手

#### 创建自定义过滤器

```java
@Component
public class KeywordFilter extends AbstractMessageFilter {
    
    @Override
    public String getName() {
        return "KeywordFilter";
    }
    
    @Override
    public int getPriority() {
        return 50; // 中等优先级
    }
    
    @Override
    protected FilterResult doFilter(TdApi.Message message, FilterContext context) {
        // 获取消息文本
        String text = extractText(message);
        
        // 检查是否包含敏感词
        if (text != null && text.contains("敏感词")) {
            context.setRejectReason("包含敏感词");
            return FilterResult.REJECT;
        }
        
        return FilterResult.ACCEPT;
    }
    
    private String extractText(TdApi.Message message) {
        if (message.content instanceof TdApi.MessageText text) {
            return text.text.text;
        }
        return null;
    }
}
```

## 3. 核心概念

### 3.1 消息生命周期

```
接收 → 过滤 → 保存 → 解析 → 处理 → 完成
```

每个阶段的职责：

1. **接收**：从 Telegram 接收原始消息
2. **过滤**：执行过滤器链，决定是否处理
3. **保存**：持久化到 MongoDB (RawMessage 集合)
4. **解析**：转换为业务实体 (BaseMessageEntity)
5. **处理**：执行插件逻辑（输出、通知等）
6. **完成**：清理资源，记录日志

### 3.2 消息类型

系统支持以下消息类型：

| 类型 | 说明 | TDLib 类型 |
|------|------|-----------|
| TEXT | 纯文本消息 | MessageText |
| PHOTO | 图片消息 | MessagePhoto |
| VIDEO | 视频消息 | MessageVideo |
| DOCUMENT | 文档消息 | MessageDocument |
| AUDIO | 音频消息 | MessageAudio |
| VOICE | 语音消息 | MessageVoiceNote |
| VIDEO_NOTE | 视频笔记 | MessageVideoNote |
| ANIMATION | 动画/GIF | MessageAnimation |
| STICKER | 贴纸 | MessageSticker |
| POLL | 投票 | MessagePoll |
| TELEGRAPH | Telegraph 文章 | MessageText (带 webPage) |
| MEDIA_GROUP | 媒体组 | 多条消息组合 |

### 3.3 过滤器优先级

优先级数字越小，执行越早：

```
10  - ChannelMonitoringFilter (频道监控)
90  - MessageTypeFilter (类型过滤)
95  - DuplicateMessageFilter (重复检测)
100 - EmptyMessageFilter (空消息)
```

### 3.4 插件优先级

优先级数字越小，执行越早：

```
100 - ConsolePrinterPlugin (控制台输出)
200 - 自定义插件
```

### 4.4 过滤器示例

#### 示例 1：频道监控过滤器（内置）

`ChannelMonitoringFilter` 是系统内置的最高优先级过滤器，负责过滤非监控频道的消息。

**特性**：
- 优先级：10（最高）
- 支持动态更新：通过 REST API 增删改频道时自动更新缓存
- 线程安全：使用 `ConcurrentHashMap` 和事件机制
- 延迟初始化：首次使用时从数据库加载监控列表

**工作原理**：

```java
@Component
public class ChannelMonitoringFilter extends AbstractMessageFilter {
    
    private final Set<Long> monitoringChannels = ConcurrentHashMap.newKeySet();
    private volatile boolean initialized = false;
    
    @Override
    public int getPriority() {
        return 10; // 最高优先级
    }
    
    @Override
    protected FilterResult doFilter(TdApi.Message message, FilterContext context) {
        // 延迟初始化
        if (!initialized) {
            synchronized (this) {
                if (!initialized) {
                    loadMonitoringChannels();
                    initialized = true;
                }
            }
        }
        
        // 检查是否为监控频道
        if (!monitoringChannels.contains(message.chatId)) {
            context.setRejectReason("非监控频道: chatId=" + message.chatId);
            return FilterResult.REJECT;
        }
        
        return FilterResult.ACCEPT;
    }
    
    // 监听频道监控事件，动态更新缓存
    @EventListener
    public void handleChannelMonitoringEvent(ChannelMonitoringEvent event) {
        switch (event.getEventType()) {
            case CHANNEL_ADDED -> handleChannelAdded(event);
            case CHANNEL_REMOVED -> handleChannelRemoved(event);
            case CHANNEL_UPDATED -> handleChannelUpdated(event);
            case RELOAD_ALL -> handleReloadAll();
        }
    }
}
```

**动态更新机制**：

当通过 REST API 操作频道时，`ChannelService` 会发布 `ChannelMonitoringEvent` 事件：

```java
@Service
public class ChannelService {
    
    private final ApplicationEventPublisher eventPublisher;
    
    @Transactional
    public ChannelVO create(ChannelCreateDTO dto) {
        // 保存频道
        Channel saved = channelRepository.save(channel);
        
        // 发布事件，通知过滤器更新缓存
        eventPublisher.publishEvent(
            ChannelMonitoringEvent.channelAdded(this, saved.getChannelId(), saved.getMonitoringStatus())
        );
        
        return convertToVO(saved);
    }
    
    @Transactional
    public ChannelVO update(String id, ChannelUpdateDTO dto) {
        // 更新频道
        Channel updated = channelRepository.save(channel);
        
        // 如果监控状态变化，发布事件
        if (!oldStatus.equals(newStatus)) {
            eventPublisher.publishEvent(
                ChannelMonitoringEvent.channelUpdated(this, updated.getChannelId(), newStatus)
            );
        }
        
        return convertToVO(updated);
    }
    
    @Transactional
    public void deleteById(String id) {
        // 删除频道
        channelRepository.deleteById(id);
        
        // 发布事件
        eventPublisher.publishEvent(
            ChannelMonitoringEvent.channelRemoved(this, channelId)
        );
    }
}
```

**事件类型**：

```java
public enum EventType {
    CHANNEL_ADDED,    // 频道被添加到监控列表
    CHANNEL_REMOVED,  // 频道从监控列表中移除
    CHANNEL_UPDATED,  // 频道监控状态被更新
    RELOAD_ALL        // 重新加载所有监控频道
}
```

**使用示例**：

```java

POST /api/channel

  "channelUsername": "tech_news",
  "channelTitle": "科技新闻",

```

**并发安全性**：

- `ConcurrentHashMap.newKeySet()` 保证并发读写安全
- `volatile` 保证 `initialized` 标志的可见性
- 双重检查锁定（DCL）保证只初始化一次
- 事件处理是异步的，不阻塞 API 调用

**性能考虑**：

- 内存查找：O(1) 时间复杂度
- 延迟初始化：避免启动时的数据库查询
- 事件驱动：只在变化时更新，不需要轮询

#### 示例 2：关键词过滤器

```java
@Component
public class KeywordFilter extends AbstractMessageFilter {
    
    private final Set<String> blacklist = Set.of("敏感词1", "敏感词2");
    
    @Override
    public String getName() {
        return "KeywordFilter";
    }
    
    @Override
    public int getPriority() {
        return 50;
    }
    
    @Override
    protected FilterResult doFilter(TdApi.Message message, FilterContext context) {
        String text = extractText(message);
        
        if (text != null) {
            for (String keyword : blacklist) {
                if (text.contains(keyword)) {
                    context.setRejectReason("包含敏感词: " + keyword);
                    return FilterResult.REJECT;
                }
            }
        }
        
        return FilterResult.ACCEPT;
    }
    
    private String extractText(TdApi.Message message) {
        if (message.content instanceof TdApi.MessageText text) {
            return text.text.text;
        } else if (message.content instanceof TdApi.MessagePhoto photo) {
            return photo.caption.text;
        } else if (message.content instanceof TdApi.MessageVideo video) {
            return video.caption.text;
        }
        return null;
    }
}
```

#### 示例 3：时间范围过滤器

```java
@Component
public class TimeRangeFilter extends AbstractMessageFilter {
    
    @Value("${filter.time-range.start-hour:9}")
    private int startHour;
    
    @Value("${filter.time-range.end-hour:18}")
    private int endHour;
    
    @Override
    public String getName() {
        return "TimeRangeFilter";
    }
    
    @Override
    public int getPriority() {
        return 60;
    }
    
    @Override
    protected FilterResult doFilter(TdApi.Message message, FilterContext context) {
        LocalDateTime dateTime = LocalDateTime.ofEpochSecond(
            message.date, 0, ZoneOffset.UTC
        );
        
        int hour = dateTime.getHour();
        
        if (hour < startHour || hour >= endHour) {
            context.setRejectReason(String.format(
                "不在工作时间: %02d:00-%02d:00", startHour, endHour
            ));
            return FilterResult.REJECT;
        }
        
        return FilterResult.ACCEPT;
    }
}
```

#### 示例 4：频率限制过滤器

```java
@Component
public class RateLimitFilter extends AbstractMessageFilter {
    
    private final Map<Long, RateLimiter> limiters = new ConcurrentHashMap<>();
    
    @Value("${filter.rate-limit.permits-per-second:10}")
    private double permitsPerSecond;
    
    @Override
    public String getName() {
        return "RateLimitFilter";
    }
    
    @Override
    public int getPriority() {
        return 70;
    }
    
    @Override
    protected FilterResult doFilter(TdApi.Message message, FilterContext context) {
        RateLimiter limiter = limiters.computeIfAbsent(
            message.chatId,
            k -> RateLimiter.create(permitsPerSecond)
        );
        
        if (!limiter.tryAcquire()) {
            context.setRejectReason("频率超限: chatId=" + message.chatId);
            return FilterResult.REJECT;
        }
        
        return FilterResult.ACCEPT;
    }
}
```

### 4.6 过滤器最佳实践

#### ✅ 好的实践

1. **无状态设计**
   ```java
   // ✅ 好：使用 final 字段
   private final Set<String> blacklist = Set.of("word1", "word2");
   
   // ❌ 坏：使用可变状态
   private int counter = 0; // 多线程不安全
   ```

2. **快速失败**
   ```java
   // ✅ 好：尽早返回
   if (text == null) {
       return FilterResult.ACCEPT;
   }
   
   // ❌ 坏：嵌套过深
   if (text != null) {
       if (text.length() > 0) {
           // ...
       }
   }
   ```

3. **清晰的拒绝原因**
   ```java
   // ✅ 好：详细的原因
   context.setRejectReason("包含敏感词: " + keyword);
   
   // ❌ 坏：模糊的原因
   context.setRejectReason("拒绝");
   ```

4. **线程安全**
   ```java
   // ✅ 好：使用线程安全的集合
   private final Set<Long> cache = ConcurrentHashMap.newKeySet();
   
   // ❌ 坏：使用非线程安全的集合
   private final Set<Long> cache = new HashSet<>();
   ```

#### ❌ 避免的做法

1. **修改消息内容**
   ```java
   // ❌ 不要修改消息
   message.content = new TdApi.MessageText(...);
   ```

2. **长时间阻塞**
   ```java
   // ❌ 不要执行耗时操作
   Thread.sleep(1000);
   httpClient.get("http://...");
   ```

3. **抛出未捕获异常**
   ```java
   // ❌ 不要抛出异常（除非继承 AbstractMessageFilter）
   throw new RuntimeException("Error");
   ```

```java
@Component

public class DatabaseSavePlugin implements MessagePlugin {
    
    private final MessageRepository messageRepository;

    public String getName() {
        return "DatabaseSavePlugin";
    }

    public int getPriority() {

        }
    }

        // 转换逻辑
        return new MessageEntity();

}
```

#### 示例 2：通知插件

```java
@Component
@RequiredArgsConstructor
public class NotificationPlugin implements MessagePlugin {
    
    private final NotificationService notificationService;
    
    @Value("${plugin.notification.enabled:true}")
    private boolean enabled;
    
    @Override
    public String getName() {
        return "NotificationPlugin";
    }
    
    @Override
    public int getPriority() {
        return 100;
    }
    
    @Override
    public void process(BaseMessageEntity entity, TdApi.Message originalMessage) {
        if (!enabled) {
            return;
        }
        
        // 只通知特定类型的消息
        if (shouldNotify(entity)) {
```

## 6.5 媒体组处理

### 什么是媒体组？

媒体组（Media Album）是 Telegram 允许用户一次性发送多个媒体文件（最多 10 个）的功能。这些文件会：
- 在聊天界面中作为一组显示
- 共享相同的说明文字
- 可以包含不同类型的媒体（图片、视频、文档、音频）

### 技术标识

在 TDLib API 中，属于同一媒体组的消息具有：
- 相同的非零 `mediaAlbumId`
- 不同的 `messageId`
- 相近的发送时间

### 处理机制

#### 1. 缓冲机制

```java
private final Map<String, List<TdApi.Message>> mediaGroupBuffer = 
    new ConcurrentHashMap<>();
private final Map<String, Long> mediaGroupTimestamps = 
    new ConcurrentHashMap<>();

private void handleMediaGroupMessage(TdApi.Message message) {
    String groupKey = message.chatId + ":" + message.mediaAlbumId;
    
    // 添加到缓冲区
    mediaGroupBuffer.computeIfAbsent(groupKey, k -> new ArrayList<>())
        .add(message);
    
    // 更新时间戳
    mediaGroupTimestamps.put(groupKey, System.currentTimeMillis());
}
```

**工作原理**：
- 收到带有 `mediaAlbumId` 的消息时，不立即处理
- 将消息添加到内存缓冲区
- 使用 `chatId:mediaAlbumId` 作为缓冲区的键
- 更新该媒体组的最后接收时间戳

#### 2. 超时机制

```java
private static final long MEDIA_GROUP_TIMEOUT = 2000; // 2秒

@Scheduled(fixedDelay = 1000)
public void processTimedOutMediaGroups() {
    long now = System.currentTimeMillis();
    List<String> timedOutGroups = new ArrayList<>();
    
    // 找出超时的媒体组
    mediaGroupTimestamps.forEach((groupKey, timestamp) -> {
        if (now - timestamp >= MEDIA_GROUP_TIMEOUT) {
            timedOutGroups.add(groupKey);
        }
    });
    
    // 处理超时的媒体组
    for (String groupKey : timedOutGroups) {
        List<TdApi.Message> messages = mediaGroupBuffer.remove(groupKey);
        mediaGroupTimestamps.remove(groupKey);
        
        if (messages != null && !messages.isEmpty()) {
            processMediaGroup(messages);
        }
    }
}
```

**为什么是 2 秒？**
- Telegram 通常在 1 秒内发送完所有媒体组消息
- 2 秒的超时提供了足够的缓冲时间
- 避免网络延迟导致的拆分

#### 3. 批量处理

```java
private void processMediaGroup(List<TdApi.Message> messages) {
    // 1. 排序
    messages.sort(Comparator.comparingLong(m -> m.id));
    
    // 2. 去重检查
    long existingCount = messageRepository.countByChatIdAndMediaAlbumId(
        chatId, mediaAlbumId);
    if (existingCount > 0) {
        return; // 已存在，跳过
    }
    
    // 3. 收集消息ID
    List<Long> messageIds = messages.stream()
        .map(m -> m.id)
        .collect(Collectors.toList());
    
    // 4. 解析并设置组信息
    List<BaseMessageEntity> parsedMessages = new ArrayList<>();
    for (TdApi.Message message : messages) {
        BaseMessageEntity entity = messageParser.parseMediaGroupItem(
            message, channelUsername, channelTitle);
        
        entity.setMediaAlbumId(mediaAlbumId);
        entity.setIsMediaGroup(true);
        entity.setMediaGroupItemCount(messages.size());
        entity.setMediaGroupMessageIds(messageIds);
        
        parsedMessages.add(entity);
    }
    
    // 5. 创建媒体组实体
    MediaGroupMessageEntity mediaGroupEntity = 
        createMediaGroupEntity(parsedMessages, mediaAlbumId);
    
    // 6. 插件处理（包括控制台输出）
    pluginManager.process(mediaGroupEntity, messages.get(0));
}
```

## 7. 并发安全性

### 7.1 媒体组状态机

为了解决媒体组处理中的并发竞态条件，系统引入了状态机机制来管理媒体组的生命周期。

#### 7.1.1 状态定义

```java
public enum MediaGroupState {
    /**
     * 收集中：正在接收媒体组的消息
     */
    COLLECTING,
    
    /**
     * 处理中：正在处理媒体组
     */
    PROCESSING,
    
    /**
     * 已完成：媒体组处理完成
     */
    COMPLETED
}
```

#### 7.1.2 状态转换规则

```
[新消息到达]
     |
     v
COLLECTING ──────超时────────> PROCESSING ──────成功────────> COMPLETED
     ^                              |
     |                              |
     └──────────失败────────────────┘
```

**转换规则**：
1. 首次接收消息 → COLLECTING
2. 超时且状态为 COLLECTING → PROCESSING
3. 处理成功 → COMPLETED
4. 处理失败 → COLLECTING（允许重试）
5. PROCESSING 或 COMPLETED 状态拒绝新消息

#### 7.1.3 使用示例

```java
@Service
public class ChannelMonitorService implements MediaGroupProcessor {
    
    // 媒体组状态机
    private final Map<String, MediaGroupState> mediaGroupStates = 
        new ConcurrentHashMap<>();
    
    @Override
    public boolean handleMediaGroupMessage(TdApi.Message message) {
        String groupKey = message.chatId + ":" + message.mediaAlbumId;
        Lock lock = getGroupLock(groupKey);
        
        lock.lock();
        try {
            // 检查当前状态
            MediaGroupState state = mediaGroupStates.get(groupKey);
            
            // 如果正在处理或已完成，拒绝新消息
            if (state == MediaGroupState.PROCESSING || 
                state == MediaGroupState.COMPLETED) {
                log.warn("媒体组 {} 状态为 {}，拒绝新消息: messageId={}", 
                    groupKey, state, message.id);
                return false;
            }
            
            // 设置为收集状态
            mediaGroupStates.putIfAbsent(groupKey, MediaGroupState.COLLECTING);
            
            // 添加消息到缓冲区
            mediaGroupBuffer.computeIfAbsent(groupKey, k -> new ArrayList<>())
                .add(message);
            
            // 更新时间戳
            mediaGroupTimestamps.put(groupKey, System.currentTimeMillis());
            
            return true;
            
        } finally {
            lock.unlock();
        }
    }
}
```

### 7.2 分段锁机制

为了减少锁竞争并提高并发处理能力，系统使用 Guava 的 Striped Lock 实现分段锁。

#### 7.2.1 分段锁原理

```
媒体组 A (chatId:albumId1) → 锁 1
媒体组 B (chatId:albumId2) → 锁 2
媒体组 C (chatId:albumId3) → 锁 1  (哈希冲突，共享锁)
媒体组 D (chatId:albumId4) → 锁 3
```

**优势**：
- 不同媒体组使用不同的锁，减少竞争
- 内存占用可控（128 个锁实例）
- 自动负载均衡

#### 7.2.2 实现方式

```java
@Service
public class ChannelMonitorService {
    
    // 分段锁（128 个锁条带）
    private final Striped<Lock> groupLocks = Striped.lock(128);
    
    /**
     * 获取媒体组的锁
     */
    private Lock getGroupLock(String groupKey) {
        return groupLocks.get(groupKey);
    }
    
    /**
     * 使用锁保护的操作
     */
    private void processWithLock(String groupKey) {
        Lock lock = getGroupLock(groupKey);
        
        lock.lock();
        try {
            // 原子操作：状态检查 + 状态更新 + 数据操作
            MediaGroupState state = mediaGroupStates.get(groupKey);
            if (state == MediaGroupState.COLLECTING) {
                mediaGroupStates.put(groupKey, MediaGroupState.PROCESSING);
                // 处理逻辑
            }
        } finally {
            lock.unlock();
        }
    }
}
```

#### 7.2.3 锁超时处理

```java
/**
 * 带超时的锁获取
 */
private boolean tryProcessWithTimeout(String groupKey) {
    Lock lock = getGroupLock(groupKey);
    
    try {
        if (lock.tryLock(5, TimeUnit.SECONDS)) {
            try {
                // 处理逻辑
                return true;
            } finally {
                lock.unlock();
            }
        } else {
            log.warn("获取锁超时: groupKey={}", groupKey);
            return false;
        }
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
        return false;
    }
}
```

### 7.5 并发安全最佳实践

#### 7.5.1 状态机使用

```java
// ✅ 好的实践：在锁保护下检查和更新状态
Lock lock = getGroupLock(groupKey);
lock.lock();
try {
    MediaGroupState state = mediaGroupStates.get(groupKey);
    if (state == MediaGroupState.COLLECTING) {
        // 状态检查和更新在同一个锁保护范围内
        mediaGroupStates.put(groupKey, MediaGroupState.PROCESSING);
        // 执行处理逻辑
    }
} finally {
    lock.unlock();
}

// ❌ 坏的实践：状态检查和更新不在同一个锁保护范围内
MediaGroupState state = mediaGroupStates.get(groupKey);  // 无锁
if (state == MediaGroupState.COLLECTING) {
    Lock lock = getGroupLock(groupKey);
    lock.lock();
    try {
        mediaGroupStates.put(groupKey, MediaGroupState.PROCESSING);  // 竞态条件
    } finally {
        lock.unlock();
    }
}
```

#### 7.5.2 缓存使用

```java
// ✅ 好的实践：依赖 TTL 自动过期
processingCache.put(cacheKey, Boolean.TRUE);

// ❌ 坏的实践：手动管理缓存生命周期
processingCache.put(cacheKey, Boolean.TRUE);
// ... 处理逻辑
processingCache.invalidate(cacheKey);  // 容易遗漏或出错
```

#### 7.5.3 错误处理

### C. 常见问题 FAQ

**Q1: 如何添加新的消息类型？**

A: 参考 [6.3 自定义类型检测](#63-自定义类型检测)

**Q2: 过滤器的执行顺序是什么？**

A: 按优先级从小到大执行，数字越小优先级越高。参考 [3.3 过滤器优先级](#33-过滤器优先级)

**Q3: 如何禁用某个过滤器？**

A: 使用 `FilterChainManager.disableFilter(filterName)` 或在配置中设置 `enabled: false`

**Q4: 插件处理失败会影响其他插件吗？**

A: 不会。每个插件独立执行，一个插件失败不影响其他插件。

**Q5: 如何处理大文件下载？**

A: 使用 TDLib 的异步下载 API，监听 `UpdateFile` 事件。参考 [Telegram频道实时监控技术方案](./Telegram频道实时监控技术方案.md)

**Q6: 系统支持多实例部署吗？**

A: 当前设计为单实例。多实例需要实现分布式锁和消息队列。参考并发安全性优化设计文档了解更多细节。

**Q7: 如何监控系统性能？**

A: 使用 Micrometer 指标和 JMX。参考 [8.3 性能分析](#83-性能分析)

**Q8: 媒体组处理有什么注意事项？**

A: 注意并发安全问题，建议使用状态机和分段锁。参考并发安全性优化设计文档了解详细的实现方案。
