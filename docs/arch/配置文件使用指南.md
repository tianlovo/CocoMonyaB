## 1. 环境变量配置 (.env)

### 1.1 配置文件位置

- **开发环境**：`data/config/.env`
- **生产环境**：`data/config/.env`

### 1.2 首次配置流程

系统首次启动时会自动处理环境配置文件：

1. **检查 data/config/.env**：如果存在，直接使用
2. **检查应用同级 .env**：如果存在，自动迁移到 data/config/
3. **首次启动**：
   - 从 resources 复制 `.env.example` 到应用同级目录
   - 提示用户填写配置
   - 退出应用，等待用户配置
4. **下次启动**：检测到同级 .env 文件，自动迁移到 data/config/

### 1.3 配置项说明

#### API_ID（必填）

- **类型**：整数
- **说明**：Telegram API ID，从 https://my.telegram.org/apps 获取
- **示例**：`12345678`
- **获取方式**：
  1. 访问 https://my.telegram.org/apps
  2. 使用手机号登录
  3. 创建新应用
  4. 复制 API ID

#### API_HASH（必填）

- **类型**：字符串（32位十六进制）
- **说明**：Telegram API Hash，与 API_ID 配套
- **示例**：`0123456789abcdef0123456789abcdef`
- **格式要求**：32个字符，仅包含 0-9 和 a-f

#### TG_PHONE（必填）

- **类型**：字符串
- **说明**：登录 Telegram 的手机号
- **格式**：`+国家代码+手机号`
- **示例**：
  - 中国：`+8613800138000`
  - 美国：`+11234567890`
  - 日本：`+819012345678`

#### TG_2FA（可选）

- **类型**：字符串
- **说明**：Telegram 两步验证密码
- **何时需要**：如果你的 Telegram 账号启用了两步验证（2FA）
- **示例**：`your_2fa_password`
- **注意事项**：
  - 如果未启用 2FA，可以留空或删除此行
  - 密码区分大小写
  - 建议使用强密码

### 1.4 .env 文件示例

```env
# Telegram API 配置
API_ID=12345678
API_HASH=0123456789abcdef0123456789abcdef
TG_PHONE=+8613800138000
TG_2FA=my_secure_password
```

### 1.5 安全建议

⚠️ **重要安全提示**：

1. **不要提交到版本控制**：`.env` 文件包含敏感信息，已在 `.gitignore` 中排除
2. **权限控制**：确保文件权限设置为仅所有者可读（Linux/macOS: `chmod 600 .env`）
3. **备份**：定期备份 `.env` 文件到安全位置
4. **密码强度**：使用强密码作为 2FA 密码
5. **定期更换**：定期更换 API 凭证和密码

## 2. 应用配置 (application.yaml)

- **主配置文件**：`src/main/resources/application.yaml`

### 2.2 Spring 应用配置

#### 应用名称

```yaml
spring:
  application:
    name: "CocoMonyaB"
```

- **说明**：应用标识名称
- **默认值**：`CocoMonyaB`
- **是否可修改**：可以，但不建议修改

### 2.3 MongoDB 配置

#### 运行模式

```yaml
spring:
  data:
    mongodb:
      mode: embedded  # embedded 或 remote
```

**embedded（嵌入式模式）**

- **适用场景**：开发环境、单机部署、快速测试
- **优点**：
  - 无需单独安装 MongoDB
  - 自动启动和管理
  - 零配置开箱即用
- **缺点**：
  - 性能略低于独立 MongoDB
  - 不支持集群
  - 数据仅存储在本地

**remote（远程模式）**

- **适用场景**：生产环境、集群部署、高性能需求
- **优点**：
  - 性能更好
  - 支持集群和副本集
  - 可以独立管理和监控
- **缺点**：
  - 需要单独安装和配置 MongoDB
  - 需要管理连接和权限

#### 嵌入式 MongoDB 配置

```yaml
spring:
  data:
    mongodb:
      embedded:
        version: 7.0.12      # MongoDB 版本
        port: 27017          # 监听端口
        bind-ip: 127.0.0.1   # 绑定 IP
```

| 配置项 | 说明 | 默认值 | 建议值 |
|--------|------|--------|--------|
| version | MongoDB 版本号 | 7.0.12 | 使用最新稳定版 |
| port | 监听端口 | 27017 | 默认即可 |
| bind-ip | 绑定 IP 地址 | 127.0.0.1 | 本地开发使用 127.0.0.1 |

#### 远程 MongoDB 配置

```yaml
spring:
  data:
    mongodb:
      mode: remote
      uri: mongodb://username:password@host:port/database
```

**URI 格式说明**：

- **基本格式**：`mongodb://host:port/database`
- **带认证**：`mongodb://username:password@host:port/database`
- **副本集**：`mongodb://host1:port1,host2:port2/database?replicaSet=rs0`
- **完整示例**：
  ```yaml
  uri: mongodb://admin:password@localhost:27017/cocomonya?authSource=admin
  ```

**常用参数**：

| 参数 | 说明 | 示例 |
|------|------|------|
| authSource | 认证数据库 | `authSource=admin` |
| replicaSet | 副本集名称 | `replicaSet=rs0` |
| ssl | 启用 SSL | `ssl=true` |
| retryWrites | 重试写入 | `retryWrites=true` |

### 2.4 服务器配置

```yaml
server:
```

- **说明**：HTTP 服务器监听端口
- **默认值**：`10721`

  - 生产环境：根据需要修改，避免端口冲突

### 2.5 日志配置

```yaml
logging:
  config: classpath:logback-spring.xml
  level:
    root: INFO
    "[it.tdlight.TDLight]": WARN
```

**日志级别说明**：

| 级别 | 说明 | 使用场景 |
|------|------|----------|
| TRACE | 最详细的日志 | 深度调试 |
| DEBUG | 调试信息 | 开发调试 |
| INFO | 一般信息 | 生产环境（推荐） |
| WARN | 警告信息 | 生产环境 |
| ERROR | 错误信息 | 所有环境 |

**自定义日志级别**：

```yaml
logging:
  level:
    root: INFO
    org.xlyo.cocomonyab: DEBUG  # 应用日志设为 DEBUG
    org.springframework: WARN    # Spring 框架日志设为 WARN
    "[it.tdlight.TDLight]": WARN # TDLight 日志设为 WARN
```

### 2.6 数据目录配置

```yaml
app:
  data:
    database-directory: "db"
    mongo-db-directory: "db/mongo"
    session-directory: "session"
    telegram-session-directory: "session/td"
    bin-directory: "bin"
    mongo-bin-directory: "bin/mongo"
    tmp-directory: "tmp"
    logs-directory: "logs"
```

**注意事项**：

- ⚠️ **data 根目录和 config 目录路径固定，不可配置**
  - data 根目录：固定为应用同级的 `data` 目录
  - config 目录：固定为 `data/config`
- ✅ 其他子目录可以通过配置自定义相对路径
- 📁 所有路径都是相对于 data 根目录的相对路径

**目录结构**：

```
data/
├── config/          # 配置文件（固定路径）
├── db/              # 数据库目录
│   └── mongo/       # MongoDB 数据
├── session/         # 会话数据
│   └── td/          # Telegram 会话
├── bin/             # 二进制文件
│   └── mongo/       # MongoDB 二进制
├── tmp/             # 临时文件
└── logs/            # 日志文件
```

详见：[DataDirectoryManager使用指南](./DataDirectoryManager使用指南.md)

### 2.8 并发安全性配置

```yaml
concurrent-safety:
  media-group:
    timeout: 2000              # 媒体组超时（毫秒）
    max-buffer-size: 1000      # 最大缓冲区大小
  
  lock:
    stripes: 128               # 分段锁数量
    timeout: 5000              # 锁超时时间（毫秒）
  
  cache:
    ttl: 10                    # 缓存过期时间（秒）
    max-size: 10000            # 最大缓存大小
    failed-message-ttl: 5      # 失败消息缓存时间（秒）
```

#### 媒体组配置

| 配置项 | 说明 | 默认值 | 调优建议 |
|--------|------|--------|----------|
| timeout | 超时时间（毫秒） | 2000 | 网络慢时增加到 3000-5000 |
| max-buffer-size | 最大缓冲区大小 | 1000 | 高并发时增加到 2000-5000 |

**超时时间说明**：

- 媒体组消息通常在 1-2 秒内全部到达
- 超时时间过短：可能导致媒体组被拆分
- 超时时间过长：增加处理延迟
- 建议值：2000-3000 毫秒

#### 锁配置

| 配置项 | 说明 | 默认值 | 调优建议 |
|--------|------|--------|----------|
| stripes | 分段锁数量 | 128 | 高并发时增加到 256 |
| timeout | 锁超时时间（毫秒） | 5000 | 一般不需要修改 |

**分段锁说明**：

- 分段锁用于减少锁竞争，提高并发性能
- 锁数量越多，并发性能越好，但内存占用也越大
- 建议值：64-256（2的幂次方）

#### 缓存配置

| 配置项 | 说明 | 默认值 | 调优建议 |
|--------|------|--------|----------|
| ttl | 缓存过期时间（秒） | 10 | 根据消息频率调整 |
| max-size | 最大缓存大小 | 10000 | 根据内存大小调整 |
| failed-message-ttl | 失败消息缓存时间（秒） | 5 | 一般不需要修改 |

详见：[消息处理流程图 - 并发安全性说明](./消息处理流程图.md#15-并发安全性说明)

### 2.9 消息来源配置

```yaml
message-source:
  unread:
    auto-detect-on-startup: true
    max-messages-per-fetch: 100
    max-total-messages: 1000
    api-call-delay: 1000
    max-retries: 3
    retry-base-delay: 2000
    retry-max-delay: 60000
    batch-size: 10
    batch-delay: 500
    buffer-ttl-days: 7
```

#### 自动检测配置

| 配置项 | 说明 | 默认值 | 建议值 |
|--------|------|--------|--------|
| auto-detect-on-startup | 启动时自动检测未读消息 | true | 生产环境建议 true |

#### API 调用配置

| 配置项 | 说明 | 默认值 | 调优建议 |
|--------|------|--------|----------|
| max-messages-per-fetch | 单次获取最大消息数 | 100 | 50-100 |
| max-total-messages | 单频道最大获取总数 | 1000 | 根据需要调整 |
| api-call-delay | API 调用延迟（毫秒） | 1000 | 避免速率限制 |

**API 速率限制说明**：

- Telegram API 有速率限制，频繁调用会被限制
- `api-call-delay` 用于控制调用频率
- 建议值：1000-2000 毫秒

#### 重试配置

| 配置项 | 说明 | 默认值 | 建议值 |
|--------|------|--------|--------|
| max-retries | 最大重试次数 | 3 | 3-5 次 |
| retry-base-delay | 基础重试延迟（毫秒） | 2000 | 2000-5000 |
| retry-max-delay | 最大重试延迟（毫秒） | 60000 | 60000 |

**重试策略**：

- 使用指数退避算法
- 第 1 次重试：2 秒后
- 第 2 次重试：4 秒后
- 第 3 次重试：8 秒后
- 最大延迟不超过 60 秒

#### 批处理配置

| 配置项 | 说明 | 默认值 | 调优建议 |
|--------|------|--------|----------|
| batch-size | 每批处理消息数 | 10 | 10-50 |
| batch-delay | 批次延迟（毫秒） | 500 | 500-1000 |

#### 缓冲区配置

| 配置项 | 说明 | 默认值 | 建议值 |
|--------|------|--------|--------|
| buffer-ttl-days | 缓冲区 TTL（天） | 7 | 7-30 天 |

详见：[消息来源生成器系统开发者指南](./消息来源生成器系统开发者指南.md)

### 2.10 插件配置

#### 频道消息存储插件

```yaml
plugin:
  channel-message-storage:
    enabled: true
```

- **说明**：将监控频道的消息存储到 `channel_messages` 数据库集合
- **优先级**：1000（最高优先级）
- **建议**：始终保持启用

#### 控制台打印插件

```yaml
plugin:
  console-printer:
    enabled: false
```

- **说明**：将消息输出到控制台
- **优先级**：0（最低优先级）
- **使用场景**：
  - 开发调试：设为 `true`
  - 生产环境：设为 `false`（避免日志过多）

#### 标签转发插件

```yaml
plugin:
  tag-based-forwarding:
    enabled: true
    target-channel-id: -1003808612339
    tag-prefix: "#"
    rate-limit-per-minute: 18
    batch-size: 10
    schedule-interval-seconds: 30
    max-retry-count: 3
    welcome-message: |
      🎊 CocoMonyaB 标签转发系统已启动
      ...
```

**配置项说明**：

| 配置项 | 说明 | 默认值 | 注意事项 |
|--------|------|--------|----------|
| enabled | 是否启用插件 | true | - |
| target-channel-id | 目标频道 ID | - | **必填**，必须为负数 |
| tag-prefix | 标签前缀 | "#" | 用于识别标签 |
| rate-limit-per-minute | 每分钟转发速率 | 18 | 避免 API 限制 |
| batch-size | 批次大小 | 10 | 每批处理消息数 |
| schedule-interval-seconds | 调度间隔（秒） | 30 | 定时任务执行间隔 |
| max-retry-count | 最大重试次数 | 3 | 转发失败重试次数 |
| welcome-message | 欢迎消息模板 | - | 支持占位符 |

**目标频道 ID 获取方式**：

1. 使用 Telegram Bot API：
   ```bash
   # 将 Bot 添加到频道，然后发送消息
   curl https://api.telegram.org/bot<YOUR_BOT_TOKEN>/getUpdates
   ```

2. 使用第三方工具：
   - Telegram Web：查看频道链接中的 ID
   - 第三方 Bot：如 @userinfobot

3. 使用系统 API：
   ```bash
   # 查询已登录账号的频道列表
   curl http://localhost:10721/api/channel/tg/logged-in
   ```

**欢迎消息占位符**：

| 占位符 | 说明 | 示例值 |
|--------|------|--------|
| {pluginName} | 插件名称 | TagBasedMessageForwardingPlugin |
| {version} | 系统版本 | 1.0.0 |
| {tagPrefix} | 标签前缀 | # |
| {rateLimitPerMinute} | 转发速率 | 18 |
| {batchSize} | 批次大小 | 10 |
| {scheduleInterval} | 调度间隔 | 30 |
| {maxRetryCount} | 最大重试次数 | 3 |

## 3. 配置优先级

### 3.1 配置加载顺序

配置按以下顺序加载，后加载的配置会覆盖先加载的：

1. **默认配置**：`application.yaml`
2. **环境特定配置**：`application-{profile}.yaml`
3. **环境变量**：`.env` 文件
4. **系统环境变量**：操作系统环境变量
5. **命令行参数**：启动时的命令行参数

### 3.2 配置覆盖示例

**application.yaml**：
```yaml
server:
  port: 10721
```

**application-prod.yaml**：
```yaml
server:
  port: 8080
```

**启动命令**：
```bash
java -jar app.jar --spring.profiles.active=prod --server.port=9090
```

**最终生效**：`server.port = 9090`

### 3.3 环境变量优先级

环境变量的优先级：

1. **命令行参数** > **系统环境变量** > **.env 文件**

示例：

```bash
# .env 文件
API_ID=12345678

# 系统环境变量
export API_ID=87654321

# 命令行参数
java -jar app.jar --env.api-id=11111111

# 最终生效：API_ID = 11111111
```

## 5. 配置验证

### 5.1 启动时验证

系统启动时会自动验证配置：

1. **环境变量验证**：
   - 检查 `.env` 文件是否存在
   - 验证必填字段（API_ID, API_HASH, TG_PHONE）
   - 验证字段格式

2. **应用配置验证**：
   - 验证端口是否被占用
   - 验证 MongoDB 连接

## 6. 故障排查

### 6.1 常见问题

#### 问题 1：找不到 .env 文件

**错误信息**：

```
未找到环境配置文件 (.env)
已在应用目录创建配置模板文件: /path/to/.env.example
```

**解决方法**：

1. 将 `.env.example` 重命名为 `.env`
2. 编辑 `.env` 文件，填写真实配置
3. 重新启动应用

#### 问题 2：API_ID 或 API_HASH 无效

**错误信息**：

```
Telegram 客户端初始化失败: Invalid API credentials
```

**解决方法**：

1. 检查 `.env` 文件中的 `API_ID` 和 `API_HASH` 是否正确
2. 确认凭证来自 https://my.telegram.org/apps
3. 确保 `API_ID` 是纯数字
4. 确保 `API_HASH` 是 32 位十六进制字符串

#### 问题 3：手机号格式错误

**错误信息**：

```
Invalid phone number format
```

**解决方法**：

1. 确保手机号以 `+` 开头
2. 包含国家代码（如中国：+86）
3. 不要包含空格或其他字符
4. 示例：`+8613800138000`

#### 问题 4：两步验证密码错误

**错误信息**：

```
Two-factor authentication password is incorrect
```

**解决方法**：

1. 检查 `.env` 文件中的 `TG_2FA` 是否正确
2. 密码区分大小写
3. 如果忘记密码，需要在 Telegram 中重置

#### 问题 5：MongoDB 连接失败

**错误信息**：

```
Failed to connect to MongoDB
```

**解决方法**：

**嵌入式模式**：
1. 检查端口 27017 是否被占用
2. 检查 `data/db/mongo` 目录权限
3. 查看日志文件 `data/logs/application.log`

**远程模式**：
1. 检查 MongoDB URI 是否正确
2. 确认 MongoDB 服务是否运行
3. 检查网络连接和防火墙设置
4. 验证用户名和密码

#### 问题 6：端口被占用

**错误信息**：

```
Port 10721 is already in use
```

**解决方法**：

1. 修改 `application.yaml` 中的 `server.port`
2. 或者停止占用该端口的进程：
   ```bash
   # Windows
   netstat -ano | findstr :10721
   taskkill /PID <PID> /F
   
   # Linux/macOS
   lsof -i :10721
   kill -9 <PID>
   ```

#### 问题 7：目标频道 ID 无效

**错误信息**：

```
Invalid target channel ID: must be negative
```

**解决方法**：

1. 确保 `target-channel-id` 是负数
2. Telegram 频道 ID 格式：`-100xxxxxxxxxx`
3. 使用 API 查询频道 ID：
   ```bash
   curl http://localhost:10721/api/channel/tg/logged-in
   ```

### 6.4 性能调优

#### 内存配置

```bash
# 启动时指定 JVM 内存参数
java -Xms512m -Xmx2g -jar CocoMonyaB-1.0.0.jar
```

**参数说明**：

- `-Xms512m`：初始堆内存 512MB
- `-Xmx2g`：最大堆内存 2GB
- 建议：初始内存设为最大内存的 1/4 到 1/2

#### 并发调优

高并发场景下的配置建议：

```yaml
concurrent-safety:
  media-group:
    timeout: 3000
    max-buffer-size: 5000
  
  lock:
    stripes: 256
    timeout: 10000
  
  cache:
    ttl: 15
    max-size: 20000
```

#### MongoDB 性能优化

```yaml
spring:
  data:
    mongodb:
      uri: mongodb://localhost:27017/cocomonya?maxPoolSize=50&minPoolSize=10
```

**连接池参数**：

- `maxPoolSize`：最大连接数（默认 100）
- `minPoolSize`：最小连接数（默认 0）
- `maxIdleTimeMS`：最大空闲时间（毫秒）
- `maxConnectionLifeTimeMS`：最大连接生命周期（毫秒）

1. **敏感信息管理**：

   - 不要将 `.env` 文件提交到版本控制
   - 定期更换 API 凭证和密码

2. **权限控制**：
   ```bash
   # Linux/macOS
   chmod 600 data/config/.env
   chmod 700 data/
   ```

3. **加密存储**：
   - 生产环境使用密钥管理服务（如 AWS KMS、Azure Key Vault）
   - 考虑使用 Spring Cloud Config 加密配置

### 7.2 配置管理最佳实践

1. **版本控制**：
   - 提交 `.env.example` 作为模板
   - 提交 `application.yaml` 默认配置
   - 不提交 `.env` 和环境特定配置

2. **文档化**：
   - 为每个配置项添加注释
   - 维护配置变更日志
   - 记录配置依赖关系

3. **环境隔离**：
   - 开发、测试、生产环境使用不同配置
   - 使用 Spring Profiles 管理环境
   - 避免在代码中硬编码配置
