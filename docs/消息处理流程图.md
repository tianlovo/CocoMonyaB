# 消息处理流程图

本文档展示了 Telegram 频道消息监控系统的完整处理流程。

## 1. 系统整体架构

```mermaid
graph TB
    A[Telegram Server] -->|UpdateNewMessage| B[TelegramClientManager]
    B -->|分发更新| C[TgUpdateNewMessageHandler]
    C -->|频道消息| D{是否为频道消息?}
    D -->|否| E[忽略]
    D -->|是| F{是否在监控列表?}
    F -->|否| G[记录日志并忽略]
    F -->|是| H[ChannelMonitorService]
    H -->|解析并保存| I[MongoDB]
    H -->|格式化输出| J[控制台]
    
    style A fill:#e1f5ff
    style B fill:#fff4e1
    style C fill:#fff4e1
    style H fill:#e8f5e9
    style I fill:#f3e5f5
    style J fill:#fce4ec
```

## 2. 应用启动流程

```mermaid
sequenceDiagram
    participant App as Spring Application
    participant TCM as TelegramClientManager
    participant CMS as ChannelMonitorService
    participant DB as MongoDB
    participant TG as Telegram Server

    App->>TCM: @PostConstruct 初始化
    TCM->>TCM: 验证配置
    TCM->>TG: 连接并登录
    TG-->>TCM: 登录成功
    TCM->>TCM: 注册 UpdateHandler
    
    App->>CMS: @PostConstruct 初始化
    CMS->>DB: 查询监控频道列表
    DB-->>CMS: 返回频道列表
    CMS->>CMS: 加载到内存缓存
    CMS-->>App: 初始化完成
    
    Note over App,TG: 系统就绪，开始监听消息
```

## 3. 消息接收和处理流程

```mermaid
flowchart TD
    Start([Telegram 新消息]) --> Receive[TelegramClientManager<br/>接收 UpdateNewMessage]
    Receive --> Dispatch[分发到 Handler]
    Dispatch --> Handler[TgUpdateNewMessageHandler<br/>onNewMessageUpdate]
    
    Handler --> CheckType{检查消息类型<br/>isChannelPost?}
    CheckType -->|否| IgnoreType[忽略非频道消息]
    CheckType -->|是| CheckMonitor{检查监控列表<br/>isMonitoring?}
    
    CheckMonitor -->|否| LogIgnore[记录日志并忽略]
    CheckMonitor -->|是| Process[ChannelMonitorService<br/>handleNewMessage]
    
    Process --> CheckDup{检查消息是否存在<br/>去重检查}
    CheckDup -->|已存在| SkipDup[跳过重复消息]
    CheckDup -->|不存在| Parse[解析消息内容]
    
    Parse --> ParseContent[parseMessage]
    ParseContent --> GetChannel[获取频道信息]
    ParseContent --> ParseType[解析消息类型]
    
    ParseType --> TypeSwitch{消息类型?}
    TypeSwitch -->|文本| ParseText[解析文本消息]
    TypeSwitch -->|图片| ParsePhoto[解析图片消息]
    TypeSwitch -->|视频| ParseVideo[解析视频消息]
    TypeSwitch -->|文档| ParseDoc[解析文档消息]
    TypeSwitch -->|其他| ParseOther[解析其他类型]
    
    ParseText --> CheckWebPage{包含 WebPage?}
    CheckWebPage -->|是| ParseWebPage[解析 WebPage 信息]
    CheckWebPage -->|否| Continue1[继续]
    
    ParseWebPage --> CheckInstant{有即时预览?}
    CheckInstant -->|是| MarkTelegraph[标记为 telegraph]
    CheckInstant -->|否| Continue2[继续]
    
    ParsePhoto --> Continue1
    ParseVideo --> Continue1
    ParseDoc --> Continue1
    ParseOther --> Continue1
    MarkTelegraph --> Continue1
    Continue2 --> Continue1
    
    Continue1 --> Save[保存到 MongoDB]
    Save --> Print[输出到控制台]
    Print --> End([处理完成])
    
    IgnoreType --> End
    LogIgnore --> End
    SkipDup --> End
    
    style Start fill:#e1f5ff
    style Process fill:#e8f5e9
    style Save fill:#f3e5f5
    style Print fill:#fce4ec
    style End fill:#e1f5ff
```

## 4. 消息内容解析详细流程

```mermaid
flowchart LR
    subgraph Input[输入]
        Msg[TdApi.Message]
    end
    
    subgraph Parse[解析过程]
        Create[创建 ChannelMessage 对象]
        Create --> Basic[设置基础字段]
        Basic --> Channel[获取频道信息]
        Channel --> Content[解析消息内容]
        
        Content --> Switch{消息类型}
        
        Switch -->|MessageText| Text[解析文本]
        Switch -->|MessagePhoto| Photo[解析图片]
        Switch -->|MessageVideo| Video[解析视频]
        Switch -->|MessageDocument| Doc[解析文档]
        Switch -->|MessageAudio| Audio[解析音频]
        Switch -->|MessageVoiceNote| Voice[解析语音]
        Switch -->|MessageVideoNote| VNote[解析视频笔记]
        Switch -->|MessageAnimation| Anim[解析动画]
        Switch -->|MessageSticker| Stick[解析贴纸]
        Switch -->|MessagePoll| Poll[解析投票]
        
        Text --> WebPage{有 WebPage?}
        WebPage -->|是| ParseWP[解析 WebPage]
        WebPage -->|否| Merge
        
        ParseWP --> InstantView{有即时预览?}
        InstantView -->|是| Telegraph[类型: telegraph]
        InstantView -->|否| Merge
        
        Photo --> ParseMedia[解析媒体文件]
        Video --> ParseMedia
        Doc --> ParseMedia
        Audio --> ParseMedia
        Voice --> ParseMedia
        VNote --> ParseMedia
        Anim --> ParseMedia
        Stick --> ParseMedia
        
        Poll --> Merge
        Telegraph --> Merge
        ParseMedia --> Merge[合并所有信息]
    end
    
    subgraph Output[输出]
        Result[ChannelMessage 对象]
    end
    
    Input --> Parse
    Parse --> Output
    
    style Input fill:#e1f5ff
    style Parse fill:#fff4e1
    style Output fill:#e8f5e9
```

## 5. Telegraph 文章识别流程

```mermaid
flowchart TD
    Start([接收文本消息]) --> Parse[解析 MessageText]
    Parse --> CheckWP{webPage 字段<br/>是否存在?}
    
    CheckWP -->|否| TextOnly[普通文本消息<br/>contentType: text]
    CheckWP -->|是| ParseWP[解析 WebPage 信息]
    
    ParseWP --> ExtractInfo[提取信息]
    ExtractInfo --> URL[url: 网页链接]
    ExtractInfo --> Title[title: 标题]
    ExtractInfo --> Author[author: 作者]
    ExtractInfo --> Desc[description: 描述]
    ExtractInfo --> Site[siteName: 网站名]
    
    URL --> CheckIV{instantViewVersion<br/>是否存在?}
    Title --> CheckIV
    Author --> CheckIV
    Desc --> CheckIV
    Site --> CheckIV
    
    CheckIV -->|否| WebPageOnly[普通网页链接<br/>contentType: text<br/>hasInstantView: false]
    CheckIV -->|是| Telegraph[Telegraph 文章<br/>contentType: telegraph<br/>hasInstantView: true]
    
    TextOnly --> Save[保存到数据库]
    WebPageOnly --> Save
    Telegraph --> Save
    
    Save --> Output[输出到控制台]
    Output --> End([完成])
    
    style Start fill:#e1f5ff
    style Telegraph fill:#4caf50,color:#fff
    style WebPageOnly fill:#ff9800,color:#fff
    style TextOnly fill:#2196f3,color:#fff
    style End fill:#e1f5ff
```

## 6. 数据库交互流程

```mermaid
sequenceDiagram
    participant CMS as ChannelMonitorService
    participant Repo as ChannelMessageRepository
    participant Mongo as MongoDB
    
    Note over CMS: 收到新消息
    
    CMS->>Repo: existsByChatIdAndMessageId(chatId, messageId)
    Repo->>Mongo: 查询唯一索引
    Mongo-->>Repo: 返回结果
    Repo-->>CMS: 是否存在
    
    alt 消息已存在
        CMS->>CMS: 记录日志并跳过
    else 消息不存在
        CMS->>CMS: 解析消息内容
        CMS->>Repo: save(channelMessage)
        Repo->>Mongo: 插入文档
        Mongo-->>Repo: 返回保存的文档
        Repo-->>CMS: 返回 ChannelMessage
        CMS->>CMS: 输出到控制台
    end
```

## 7. 监控频道管理流程

```mermaid
stateDiagram-v2
    [*] --> 应用启动
    
    应用启动 --> 初始化监控服务: @PostConstruct
    
    初始化监控服务 --> 查询数据库: 加载监控频道
    查询数据库 --> 加载到缓存: monitoringStatus = true
    
    加载到缓存 --> 监听中: 系统就绪
    
    监听中 --> 检查消息: 收到新消息
    检查消息 --> 监听中: 不在监控列表
    检查消息 --> 处理消息: 在监控列表
    处理消息 --> 监听中: 处理完成
    
    监听中 --> 重新加载: 调用 reloadMonitoringChannels()
    重新加载 --> 查询数据库
    
    监听中 --> 添加频道: 调用 startMonitoring(chatId)
    添加频道 --> 监听中: 添加到缓存
    
    监听中 --> 移除频道: 调用 stopMonitoring(chatId)
    移除频道 --> 监听中: 从缓存移除
    
    监听中 --> 应用关闭: @PreDestroy
    应用关闭 --> [*]
```

## 8. 错误处理流程

```mermaid
flowchart TD
    Start([消息处理开始]) --> TryCatch{Try-Catch 块}
    
    TryCatch -->|正常| CheckExists[检查消息是否存在]
    TryCatch -->|异常| CatchError[捕获异常]
    
    CheckExists -->|已存在| LogSkip[记录跳过日志]
    CheckExists -->|不存在| ParseMsg[解析消息]
    
    ParseMsg --> TryParse{解析是否成功?}
    TryParse -->|成功| SaveDB[保存到数据库]
    TryParse -->|失败| LogParseError[记录解析错误]
    
    SaveDB --> TrySave{保存是否成功?}
    TrySave -->|成功| PrintConsole[输出到控制台]
    TrySave -->|失败| LogSaveError[记录保存错误]
    
    PrintConsole --> Success([处理成功])
    
    CatchError --> LogError[记录错误日志]
    LogError --> ErrorDetails[输出错误详情<br/>chatId, messageId]
    ErrorDetails --> Continue([继续处理下一条])
    
    LogSkip --> Continue
    LogParseError --> Continue
    LogSaveError --> Continue
    
    style Start fill:#e1f5ff
    style Success fill:#4caf50,color:#fff
    style Continue fill:#ff9800,color:#fff
    style CatchError fill:#f44336,color:#fff
    style LogError fill:#f44336,color:#fff
```

## 9. 完整的端到端流程

```mermaid
sequenceDiagram
    participant User as 用户
    participant TG as Telegram Server
    participant TCM as TelegramClientManager
    participant Handler as TgUpdateNewMessageHandler
    participant CMS as ChannelMonitorService
    participant Repo as Repository
    participant DB as MongoDB
    participant Console as 控制台
    
    User->>TG: 在频道发送消息
    TG->>TCM: 推送 UpdateNewMessage
    TCM->>Handler: 分发更新事件
    
    Handler->>Handler: 检查 isChannelPost
    alt 不是频道消息
        Handler->>Handler: 忽略
    else 是频道消息
        Handler->>CMS: 检查 isMonitoring(chatId)
        
        alt 不在监控列表
            CMS-->>Handler: false
            Handler->>Console: 记录调试日志
        else 在监控列表
            CMS-->>Handler: true
            Handler->>CMS: handleNewMessage(message)
            
            CMS->>Repo: existsByChatIdAndMessageId()
            Repo->>DB: 查询
            DB-->>Repo: 结果
            Repo-->>CMS: 是否存在
            
            alt 消息已存在
                CMS->>Console: 记录跳过日志
            else 消息不存在
                CMS->>CMS: parseMessage()
                Note over CMS: 解析消息内容<br/>解析 WebPage<br/>判断 Telegraph
                
                CMS->>Repo: save(channelMessage)
                Repo->>DB: 插入文档
                DB-->>Repo: 保存成功
                Repo-->>CMS: 返回对象
                
                CMS->>Console: printMessageToConsole()
                Console->>Console: 格式化输出
                Note over Console: 显示频道信息<br/>显示消息内容<br/>显示 WebPage 信息<br/>显示媒体文件<br/>显示互动统计
            end
        end
    end
```

## 流程图说明

### 图表类型说明

1. **graph TB/LR** - 基础流程图（从上到下/从左到右）
2. **flowchart TD/LR** - 增强流程图，支持更多形状
3. **sequenceDiagram** - 时序图，展示组件间交互
4. **stateDiagram-v2** - 状态机图，展示状态转换

### 节点形状说明

- `[]` - 矩形：普通处理步骤
- `{}` - 菱形：判断/决策点
- `()` - 圆角矩形：开始/结束
- `[()]` - 圆形：状态节点

### 颜色说明

- 蓝色 (#e1f5ff) - 输入/开始
- 黄色 (#fff4e1) - 处理中
- 绿色 (#e8f5e9) - 核心服务
- 紫色 (#f3e5f5) - 数据库
- 粉色 (#fce4ec) - 输出/显示
