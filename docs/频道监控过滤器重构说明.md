# 频道监控过滤器重构说明

## 重构目标

将频道监控逻辑从 `ChannelMonitorService` 和 `TgUpdateNewMessageHandler` 中提取出来，改为过滤器实现，使架构更加清晰和统一。

## 重构前的架构

### 问题

1. **职责混乱**：`TgUpdateNewMessageHandler` 和 `ChannelMonitorService` 都有监控检查逻辑
2. **不一致**：监控检查在过滤器链之前执行，与其他过滤逻辑分离
3. **难以扩展**：如果需要添加其他频道级别的过滤条件，需要修改多个地方

### 原有流程

```
TgUpdateNewMessageHandler
  ├─ 检查是否为频道消息
  ├─ 检查是否为监控频道 ❌ (硬编码检查)
  └─ 调用 ChannelMonitorService.handleNewMessage()
       ├─ 执行过滤器链
       └─ 处理消息
```

## 重构后的架构

### 改进

1. **职责清晰**：监控检查完全由 `ChannelMonitoringFilter` 负责
2. **统一流程**：所有过滤逻辑都在过滤器链中执行
3. **易于扩展**：新增过滤条件只需添加新的过滤器

### 新流程

```
TgUpdateNewMessageHandler
  ├─ 检查是否为频道消息
  └─ 调用 ChannelMonitorService.handleNewMessage()
       └─ 执行过滤器链
            ├─ ChannelMonitoringFilter (priority 10) ✓ 最高优先级
            ├─ MessageTypeFilter (priority 90)
            ├─ DuplicateMessageFilter (priority 95)
            ├─ EmptyMessageFilter (priority 100)
            └─ ... 其他过滤器
       └─ 处理消息
```

## 过滤器优先级设计

| 过滤器 | 优先级 | 说明 |
|--------|--------|------|
| ChannelMonitoringFilter | 10 | 最高优先级，非监控频道直接拒绝 |
| MessageTypeFilter | 90 | 按消息类型过滤 |
| DuplicateMessageFilter | 95 | 过滤重复消息 |
| EmptyMessageFilter | 100 | 过滤空消息 |

### 优先级设计原则

1. **ChannelMonitoringFilter (10)** - 最高优先级
   - 原因：如果不是监控频道，后续所有检查都没有意义
   - 效果：尽早拒绝，节省资源

2. **MessageTypeFilter (90)** - 第二优先级
   - 原因：按类型过滤可以避免不必要的数据库查询
   - 效果：在检查重复之前先过滤掉不需要的类型

3. **DuplicateMessageFilter (95)** - 第三优先级
   - 原因：需要查询数据库，相对耗时
   - 效果：在确认消息类型后再检查重复

4. **EmptyMessageFilter (100)** - 较低优先级
   - 原因：检查逻辑简单，放在后面也不影响性能
   - 效果：最后过滤空消息

## 实现细节

### 1. 创建 ChannelMonitoringFilter

```java
@Component
public class ChannelMonitoringFilter extends AbstractMessageFilter {
    
    private static final int PRIORITY = 10; // 最高优先级
    
    private final ChannelRepository channelRepository;
    private final Set<Long> monitoringChannels = ConcurrentHashMap.newKeySet();
    private volatile boolean initialized = false;
    
    @Override
    protected FilterResult doFilter(TdApi.Message message, FilterContext context) {
        // 延迟初始化
        if (!initialized) {
            synchronized (this) {
                if (!initialized) {
                    loadMonitoringChannels();
                    initialized = true;
                }
            }
        }
        
        // 检查是否为监控频道
        if (!monitoringChannels.contains(message.chatId)) {
            context.setRejectReason(String.format(
                "非监控频道: chatId=%d", message.chatId
            ));
            return FilterResult.REJECT;
        }
        
        return FilterResult.ACCEPT;
    }
    
    // ... 其他管理方法
}
```

### 2. 修改 ChannelMonitorService

移除监控检查逻辑，保留管理方法（委托给过滤器）：

```java
@Service
public class ChannelMonitorService {
    
    private final ChannelMonitoringFilter channelMonitoringFilter;
    
    // 移除了 monitoringChannels 缓存
    // 移除了 @PostConstruct initialize() 方法
    
    /**
     * 检查频道是否在监控列表中
     * 委托给 ChannelMonitoringFilter
     */
    public boolean isMonitoring(long chatId) {
        return channelMonitoringFilter.isMonitoring(chatId);
    }
    
    /**
     * 启动监控
     * 委托给 ChannelMonitoringFilter
     */
    public void startMonitoring(long chatId) {
        channelMonitoringFilter.startMonitoring(chatId);
    }
    
    // ... 其他委托方法
}
```

### 3. 简化 TgUpdateNewMessageHandler

移除监控检查：

```java
@Component
public class TgUpdateNewMessageHandler {
    
    private final ChannelMonitorService channelMonitorService;
    
    public void onNewMessageUpdate(TdApi.UpdateNewMessage update) {
        TdApi.Message message = update.message;
        
        // 只处理频道消息
        if (!message.isChannelPost) {
            return;
        }
        
        // 处理消息（监控检查由 ChannelMonitoringFilter 完成）
        channelMonitorService.handleNewMessage(message);
    }
}
```

## 技术亮点

### 1. 延迟初始化

使用双重检查锁定（Double-Checked Locking）实现线程安全的延迟初始化：

```java
if (!initialized) {
    synchronized (this) {
        if (!initialized) {
            loadMonitoringChannels();
            initialized = true;
        }
    }
}
```

优点：
- 避免在应用启动时立即加载（提高启动速度）
- 第一次调用时才加载（按需加载）
- 线程安全

### 2. 委托模式

`ChannelMonitorService` 保留了原有的公共 API，但实现委托给 `ChannelMonitoringFilter`：

```java
public boolean isMonitoring(long chatId) {
    return channelMonitoringFilter.isMonitoring(chatId);
}
```

优点：
- 保持向后兼容
- 不影响现有代码
- 职责清晰分离

### 3. 过滤器自动注册

`ChannelMonitoringFilter` 使用 `@Component` 注解，会被 `FilterAutoConfiguration` 自动扫描和注册：

```java
@Component
public class ChannelMonitoringFilter extends AbstractMessageFilter {
    // ...
}
```

无需手动配置，Spring 会自动：
1. 创建 Bean
2. 注入到 `FilterChainManager`
3. 按优先级排序

## 效果

1. **架构更清晰**：所有过滤逻辑统一在过滤器链中
2. **职责更明确**：每个组件只负责自己的功能
3. **易于扩展**：添加新的过滤条件只需创建新的过滤器
4. **性能优化**：最高优先级过滤器尽早拒绝不需要的消息

## 未来扩展

基于这个架构，可以轻松添加更多过滤器：

- `ChannelPermissionFilter` - 频道权限检查
- `RateLimitFilter` - 频率限制
- `ContentFilter` - 内容过滤（敏感词等）
- `TimeRangeFilter` - 时间范围过滤

只需：
1. 继承 `AbstractMessageFilter`
2. 实现 `doFilter()` 方法
3. 设置合适的优先级
4. 添加 `@Component` 注解

系统会自动注册和使用新的过滤器。
