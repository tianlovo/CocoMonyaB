# 媒体组（消息组）支持说明

## 概述

系统现已支持 Telegram 媒体组（Media Album）的智能处理。媒体组是 Telegram 中将多个媒体文件作为一组发送的功能，系统会自动识别并将其作为一个整体进行处理和展示。

## 什么是媒体组？

### 定义

媒体组（Media Album）是 Telegram 允许用户一次性发送多个媒体文件（最多 10 个）的功能。这些文件会：
- 在聊天界面中作为一组显示
- 共享相同的说明文字
- 可以包含不同类型的媒体（图片、视频、文档、音频）

### 技术标识

在 TDLib API 中，属于同一媒体组的消息具有：
- 相同的非零 `mediaAlbumId`
- 不同的 `messageId`
- 相近的发送时间

## 处理机制

### 1. 缓冲机制

```
收到消息 → 检查 mediaAlbumId → 添加到缓冲区 → 等待更多消息
```

**工作原理**：
- 当收到带有 `mediaAlbumId` 的消息时，不立即处理
- 将消息添加到内存缓冲区
- 使用 `chatId:mediaAlbumId` 作为缓冲区的键
- 更新该媒体组的最后接收时间戳

**代码实现**：
```java
private final Map<String, List<TdApi.Message>> mediaGroupBuffer = 
    new ConcurrentHashMap<>();
private final Map<String, Long> mediaGroupTimestamps = 
    new ConcurrentHashMap<>();

private void handleMediaGroupMessage(TdApi.Message message) {
    String groupKey = message.chatId + ":" + message.mediaAlbumId;
    
    // 添加到缓冲区
    mediaGroupBuffer.computeIfAbsent(groupKey, k -> new ArrayList<>())
        .add(message);
    
    // 更新时间戳
    mediaGroupTimestamps.put(groupKey, System.currentTimeMillis());
}
```

### 2. 超时机制

```
定时任务（每秒） → 检查时间戳 → 超过2秒 → 触发处理
```

**工作原理**：
- 定时任务每秒检查一次所有缓冲的媒体组
- 如果某个媒体组 2 秒内没有新消息，认为该组已完整
- 从缓冲区移除并触发批量处理

**为什么是 2 秒？**
- Telegram 通常在 1 秒内发送完所有媒体组消息
- 2 秒的超时提供了足够的缓冲时间
- 避免网络延迟导致的拆分

**代码实现**：
```java
@Scheduled(fixedDelay = 1000)
public void processTimedOutMediaGroups() {
    long now = System.currentTimeMillis();
    List<String> timedOutGroups = new ArrayList<>();
    
    // 找出超时的媒体组
    mediaGroupTimestamps.forEach((groupKey, timestamp) -> {
        if (now - timestamp >= MEDIA_GROUP_TIMEOUT) {
            timedOutGroups.add(groupKey);
        }
    });
    
    // 处理超时的媒体组
    for (String groupKey : timedOutGroups) {
        List<TdApi.Message> messages = mediaGroupBuffer.remove(groupKey);
        mediaGroupTimestamps.remove(groupKey);
        
        if (messages != null && !messages.isEmpty()) {
            processMediaGroup(messages);
        }
    }
}
```

### 3. 批量处理

```
排序 → 去重检查 → 解析每条消息 → 设置组信息 → 批量保存 → 统一输出
```

**处理步骤**：

1. **排序**：按消息 ID 排序，确保顺序一致
2. **去重**：检查数据库中是否已存在该媒体组
3. **解析**：解析每条消息的内容
4. **设置组信息**：
   - `mediaAlbumId`: 媒体组 ID
   - `isMediaGroup`: true
   - `mediaGroupItemCount`: 组内消息数量
   - `mediaGroupMessageIds`: 所有消息 ID 列表
5. **保存**：批量保存到数据库
6. **输出**：统一输出到控制台

**代码实现**：
```java
private void processMediaGroup(List<TdApi.Message> messages) {
    // 1. 排序
    messages.sort(Comparator.comparingLong(m -> m.id));
    
    // 2. 去重检查
    long existingCount = messageRepository.countByChatIdAndMediaAlbumId(
        chatId, mediaAlbumId);
    if (existingCount > 0) {
        return; // 已存在，跳过
    }
    
    // 3. 收集消息ID
    List<Long> messageIds = messages.stream()
        .map(m -> m.id)
        .collect(Collectors.toList());
    
    // 4. 解析并设置组信息
    List<ChannelMessage> savedMessages = new ArrayList<>();
    for (TdApi.Message message : messages) {
        ChannelMessage channelMessage = parseMessage(message);
        
        channelMessage.setMediaAlbumId(mediaAlbumId);
        channelMessage.setIsMediaGroup(true);
        channelMessage.setMediaGroupItemCount(messages.size());
        channelMessage.setMediaGroupMessageIds(messageIds);
        
        savedMessages.add(messageRepository.save(channelMessage));
    }
    
    // 5. 统一输出
    printMediaGroupToConsole(savedMessages, messages);
}
```

### 查询所有媒体组

```javascript

    isMediaGroup: true
}).sort({createTime: -1})
```

### 统计媒体组

```javascript
// 统计每个频道的媒体组数量
db.channel_messages.aggregate([
    {$match: {isMediaGroup: true}},
    {$group: {
        _id: {
            chatId: "$chatId",
            mediaAlbumId: "$mediaAlbumId"
        },
        count: {$sum: 1},
        channelTitle: {$first: "$channelTitle"}
    }},
    {$group: {
        _id: "$channelTitle",
        groupCount: {$sum: 1},
        totalMessages: {$sum: "$count"}
    }},
    {$sort: {groupCount: -1}}
])
```

### 查询包含特定类型的媒体组

```javascript
// 查询包含视频的媒体组
db.channel_messages.find({
    isMediaGroup: true,
    contentType: "video"
}).distinct("mediaAlbumId")

// 然后查询这些媒体组的所有消息
db.channel_messages.find({
    mediaAlbumId: {$in: [/* 上面查询的结果 */]}
})
```

### 查询媒体组的完整信息

```javascript
// 使用聚合查询获取媒体组的完整信息
db.channel_messages.aggregate([
    {$match: {
        chatId: -1001234567890,
        isMediaGroup: true
    }},
    {$group: {
        _id: "$mediaAlbumId",
        messages: {$push: "$$ROOT"},
        count: {$sum: 1},
        firstMessage: {$first: "$$ROOT"}
    }},
    {$project: {
        mediaAlbumId: "$_id",
        messageCount: "$count",
        channelTitle: "$firstMessage.channelTitle",
        date: "$firstMessage.date",
        messages: {
            $map: {
                input: "$messages",
                as: "msg",
                in: {
                    messageId: "$$msg.messageId",
                    contentType: "$$msg.contentType",
                    textContent: "$$msg.textContent"
                }
            }
        }
    }},
    {$sort: {date: -1}}
])
```

## 性能考虑

### 内存管理

**缓冲区大小**：
- 通常情况下，缓冲区中同时存在的媒体组不超过 10 个
- 每个媒体组最多 10 条消息
- 总内存占用通常小于 1MB

**自动清理**：
- 超时后自动从缓冲区移除
- 避免内存泄漏
- 使用 ConcurrentHashMap 保证线程安全

### 处理延迟

**延迟分析**：
- 媒体组有 2 秒的等待时间
- 单条消息立即处理（无延迟）
- 权衡：完整性 vs 实时性

**优化建议**：
- 如果需要更快的响应，可以减少超时时间（最低 1 秒）
- 如果网络不稳定，可以增加超时时间（最高 5 秒）

### 数据库优化

**索引策略**：
```javascript
// 复合索引：快速查询媒体组
db.channel_messages.createIndex({
    chatId: 1,
    mediaAlbumId: 1,
    date: 1
})

// 单字段索引：快速过滤
db.channel_messages.createIndex({isMediaGroup: 1})
```

**查询优化**：
- 使用 `countByChatIdAndMediaAlbumId` 快速去重
- 使用 `findByChatIdAndMediaAlbumId` 批量查询
- 避免全表扫描

## 故障排查

### 问题 1：媒体组被拆分显示

**可能原因**：
- 网络延迟导致消息接收间隔超过 2 秒
- 定时任务未正常运行

**解决方法**：
1. 检查日志中的时间戳
2. 增加超时时间（修改 `MEDIA_GROUP_TIMEOUT`）
3. 确认 `@EnableScheduling` 注解已添加

### 问题 2：媒体组重复处理

**可能原因**：
- 去重检查失败
- 数据库索引未创建

**解决方法**：
1. 检查数据库索引
2. 查看日志中的去重提示
3. 手动创建复合索引

### 问题 3：内存占用过高

**可能原因**：
- 缓冲区未及时清理
- 大量媒体组同时处理

**解决方法**：
1. 检查定时任务是否正常运行
2. 监控缓冲区大小
3. 减少超时时间
