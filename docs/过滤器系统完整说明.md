# 消息过滤器系统完整说明

## 概述

消息过滤器系统用于在消息交给插件处理之前进行过滤，被过滤的消息不会记录到数据库中，也不会被插件处理。

## 架构设计

### 核心组件

1. **MessageFilter** - 过滤器接口
2. **FilterResult** - 过滤结果枚举（ACCEPT/REJECT）
3. **FilterContext** - 过滤上下文，用于在过滤器之间传递信息
4. **AbstractMessageFilter** - 抽象基类，提供错误处理
5. **FilterChainManager** - 过滤器链管理器
6. **FilterAutoConfiguration** - 自动配置类

### 执行流程

```
消息到达
  ↓
TgUpdateNewMessageHandler
  ↓
ChannelMonitorService.handleNewMessage()
  ↓
FilterChainManager.executeChain()
  ├─ ChannelMonitoringFilter (priority 10)
  ├─ MessageTypeFilter (priority 90)
  ├─ DuplicateMessageFilter (priority 95)
  └─ EmptyMessageFilter (priority 100)
  ↓
如果通过所有过滤器
  ↓
保存到数据库 + 插件处理
```

## 内置过滤器

### 1. ChannelMonitoringFilter (优先级: 10)

**功能**：只允许监控列表中的频道消息通过

**优先级**：10（最高优先级）

**原因**：如果不是监控频道，后续所有处理都没有意义，尽早拒绝可以节省资源

**配置**：无需配置，自动从数据库加载监控频道列表

**示例**：
```java
// 检查是否为监控频道
if (!monitoringChannels.contains(message.chatId)) {
    return FilterResult.REJECT;
}
```

### 2. MessageTypeFilter (优先级: 90)

**功能**：按消息类型过滤（支持黑名单和白名单模式）

**优先级**：90

**原因**：按类型过滤可以避免不必要的数据库查询

**配置**：通过 `application.yml` 配置

```yaml
filter:
  message-type:
    enabled: true
    mode: blacklist  # 或 whitelist
    types:
      - STICKER
      - POLL
```

**模式说明**：
- `blacklist`（黑名单）：拒绝指定类型的消息
- `whitelist`（白名单）：只接受指定类型的消息

### 3. DuplicateMessageFilter (优先级: 95)

**功能**：避免插件重复处理已保存的消息

**优先级**：95

**原因**：需要查询数据库，相对耗时，在确认消息类型后再检查重复

**检查机制**：
- **两层检查**：
  1. 内存缓存：快速检查正在处理的消息（解决并发竞态问题）
  2. 数据库查询：检查已保存的消息（持久化去重）

**检查逻辑**：
- 单条消息：使用 `chatId + messageId`
- 媒体组消息：使用 `chatId + mediaAlbumId`

**示例**：
```java
// 第一层：内存缓存
if (!processingMessages.add(cacheKey)) {
    return FilterResult.REJECT; // 正在处理中
}

// 第二层：数据库查询
if (rawMessageRepository.existsByChatIdAndMessageId(...)) {
    return FilterResult.REJECT; // 已存在
}
```

### 4. EmptyMessageFilter (优先级: 100)

**功能**：过滤空消息（没有任何内容的消息）

**优先级**：100（较低优先级）

**原因**：检查逻辑简单，放在后面也不影响性能

**检查条件**：
- 文本消息：`textContent` 为空或只包含空白字符
- 其他类型：不过滤

## 过滤器优先级设计

| 过滤器 | 优先级 | 执行顺序 | 说明 |
|--------|--------|----------|------|
| ChannelMonitoringFilter | 10 | 1 | 最高优先级，非监控频道直接拒绝 |
| MessageTypeFilter | 90 | 2 | 按消息类型过滤 |
| DuplicateMessageFilter | 95 | 3 | 过滤重复消息 |
| EmptyMessageFilter | 100 | 4 | 过滤空消息 |

**优先级规则**：数字越小，优先级越高，越早执行

## 自定义过滤器

### 步骤 1：创建过滤器类

```java
package org.xlyo.cocomonyab.filter.impl;

import it.tdlight.jni.TdApi;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Component;
import org.xlyo.cocomonyab.filter.AbstractMessageFilter;
import org.xlyo.cocomonyab.filter.FilterContext;
import org.xlyo.cocomonyab.filter.FilterResult;

@Slf4j
@Component
public class MyCustomFilter extends AbstractMessageFilter {
    
    private static final int PRIORITY = 50; // 设置优先级
    
    @Override
    public String getName() {
        return "MyCustomFilter";
    }
    
    @Override
    public int getPriority() {
        return PRIORITY;
    }
    
    @Override
    protected FilterResult doFilter(TdApi.Message message, FilterContext context) {
        // 实现过滤逻辑
        if (shouldReject(message)) {
            context.setRejectReason("自定义拒绝原因");
            log.debug("过滤消息: {}", message.id);
            return FilterResult.REJECT;
        }
        
        return FilterResult.ACCEPT;
    }
    
    private boolean shouldReject(TdApi.Message message) {
        // 自定义判断逻辑
        return false;
    }
}
```

### 步骤 2：自动注册

添加 `@Component` 注解后，过滤器会被自动注册到过滤器链中，无需手动配置。

### 步骤 3：设置优先级

根据过滤器的功能选择合适的优先级：

- **1-20**：最高优先级，用于基础检查（如频道监控）
- **21-50**：高优先级，用于快速过滤（如类型检查）
- **51-80**：中等优先级，用于业务逻辑过滤
- **81-100**：低优先级，用于内容检查（如空消息、重复消息）

## FilterContext 使用

`FilterContext` 用于在过滤器之间传递信息：

```java
// 设置拒绝原因
context.setRejectReason("消息为空");

// 设置自定义属性
context.setAttribute("key", value);

// 获取自定义属性
Object value = context.getAttribute("key");
```

## 错误处理

`AbstractMessageFilter` 提供了统一的错误处理：

```java
@Override
public final FilterResult filter(TdApi.Message message, FilterContext context) {
    try {
        return doFilter(message, context);
    } catch (Exception e) {
        log.error("过滤器 {} 执行失败: {}", getName(), e.getMessage(), e);
        // 发生错误时默认接受消息，避免因过滤器错误导致消息丢失
        return FilterResult.ACCEPT;
    }
}
```

**错误处理策略**：
- 过滤器抛出异常时，默认接受消息（ACCEPT）
- 记录错误日志
- 不影响其他过滤器的执行

## 性能优化

### 1. 优先级设计

将快速检查放在前面，耗时检查放在后面：

```
ChannelMonitoringFilter (内存查找) → 快
MessageTypeFilter (简单判断) → 快
DuplicateMessageFilter (数据库查询) → 慢
EmptyMessageFilter (字符串检查) → 快
```

### 2. 缓存机制

`ChannelMonitoringFilter` 和 `DuplicateMessageFilter` 都使用内存缓存：

```java
// 频道监控缓存
private final Set<Long> monitoringChannels = ConcurrentHashMap.newKeySet();

// 重复消息缓存
private final Set<String> processingMessages = ConcurrentHashMap.newKeySet();
```

### 3. 延迟初始化

`ChannelMonitoringFilter` 使用延迟初始化，避免启动时加载：

```java
if (!initialized) {
    synchronized (this) {
        if (!initialized) {
            loadMonitoringChannels();
            initialized = true;
        }
    }
}
```

## 最佳实践

### 1. 过滤器职责单一

每个过滤器只负责一种过滤逻辑：

✅ 好的设计：
- `ChannelMonitoringFilter` - 只检查频道监控
- `DuplicateMessageFilter` - 只检查重复消息

❌ 不好的设计：
- `ComplexFilter` - 同时检查频道、类型、重复等

### 2. 合理设置优先级

根据过滤器的功能和性能特点设置优先级：

✅ 好的设计：
- 快速检查优先（如频道监控）
- 耗时检查靠后（如数据库查询）

❌ 不好的设计：
- 数据库查询放在最前面
- 简单检查放在最后面

### 3. 提供清晰的拒绝原因

```java
// ✅ 好的拒绝原因
context.setRejectReason("非监控频道: chatId=" + message.chatId);

// ❌ 不好的拒绝原因
context.setRejectReason("拒绝");
```

### 4. 使用缓存提高性能

对于频繁查询的数据，使用内存缓存：

```java
// ✅ 使用缓存
private final Set<Long> cache = ConcurrentHashMap.newKeySet();

// ❌ 每次都查询数据库
repository.findById(id);
```

## 常见问题

### Q1: 过滤器的执行顺序是什么？

A: 按优先级从小到大执行，数字越小优先级越高。

### Q2: 如果过滤器抛出异常会怎样？

A: 默认接受消息（ACCEPT），记录错误日志，不影响其他过滤器。

### Q3: 如何禁用某个过滤器？

A: 从 Spring 容器中移除该过滤器的 Bean，或者在过滤器中添加启用/禁用配置。

### Q4: 过滤器可以修改消息吗？

A: 不建议。过滤器的职责是判断消息是否应该被处理，不应该修改消息内容。

### Q5: 如何测试自定义过滤器？

A: 创建单元测试，模拟 `TdApi.Message` 和 `FilterContext`：

```java
@Test
void testFilter() {
    TdApi.Message message = new TdApi.Message();
    message.chatId = 123L;
    
    FilterContext context = new FilterContext();
    FilterResult result = filter.filter(message, context);
    
    assertEquals(FilterResult.REJECT, result);
}
```

## 总结

消息过滤器系统提供了一个灵活、可扩展的消息过滤机制：

1. **统一流程**：所有过滤逻辑在过滤器链中执行
2. **易于扩展**：添加新过滤器只需创建类并添加 `@Component`
3. **性能优化**：通过优先级和缓存机制提高性能
4. **错误容错**：过滤器错误不影响消息处理
5. **清晰日志**：便于监控和调试

通过合理使用过滤器系统，可以有效地控制消息处理流程，提高系统的可维护性和扩展性。
